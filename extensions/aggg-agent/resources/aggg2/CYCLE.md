# CYCLE — повторяемый цикл работы

Рабочий цикл AGGG2.0: любая задача (от мелкой до большой) — один виток
цикла. Фазы повторяются каждый раз, правила не зависят от «прошлый раз
помню». Основано на fable-method/fable-loop (PLAN→EXECUTE→VERIFY→AUDIT):
наш task-cycle = адаптация fable-method под AGGG2.0 (добавлены база,
веб-ресёрч, находки в research.db) + правилах AGENTS/CLAUDE/CAMOUFOX/
DB-FIRST/AGENT-LSP/CODE-GRAPH.

```
        ┌─────────── ВИТОК ЗАДАЧИ ───────────┐
        │  0. ПЕРЕОСМЫСЛЕНИЕ (саммари)       │
        │  1. БАЗА (уже было? находки?)      │
        │  2. ВЕБ-РЕСЁРЧ (Camoufox, ДО)     │
        │  3. ПЛАН (критерий готовности)     │
        │  4. ДЕЙСТВИЕ (код/правки)          │
        │  5. ПРОВЕРКА (QA/CI/живьём)        │
        │  6. НАХОДКИ (research.db)          │
        │  7. ДОКУМЕНТИРОВАНИЕ (если нужно)  │
        │  8. ОТЧЁТ (коротко, результат)     │
        └────────────────────────────────────┘
                 результат → правила → новый виток
```

## Фазы (повторяются на КАЖДОЙ задаче)

**Скиллы по типу задачи — до начала работы** (обязательные): nodumb
(дорогие развилки), ask-nodumb (продукт/UX), changelog-discipline (код),
system-feedback (после действий). Их чтение на задаче соответствующего
типа — фаза цикла (список — в aggg2-mandatory-reads).

**0. Переосмысление — саммари запроса.** Что от меня хотят, одной-двумя
фразами (задача + цель). Не совпадает с буквой запроса — уточнить ДО
действий, не выполнять вслепую. Нетривиальная задача → `tasks.py add`
(журнал задач). **Re-pass при шуме (arXiv 2404.09754):** запрос с
опечатками/словом-перевёртышем — ДО действия перескажи своими словами,
сверь по КОНТЕКСТУ, не по букве одного слова. **Просьба в конце сообщения:**
последняя строка длинного сообщения часто и есть задача — читай конец
первым. **Когда уточнять (INTENT-SIM, arXiv 2311.09469):** только если цена
ошибки выше цены вопроса; иначе — назвать допущение вслух и действовать
(Google ACT: overhedge or guess — дефект).

**1. База — сначала.** «Мы это уже разбирали / к чему пришли» →
`findings.py search` + `search.py` (проектные базы) + локальные базы знаний
(skill-knowledge.db/context-internet.db, скилл local-databases) +
wiki (`db: wiki`). Память сессии — не источник. Найденное — факты, остальное
— гипотезы. **Механика (детали — core.txt п.2, AGENTS.md):** repomap первой
(1а), скиллы ПЕРЕД вебом по типу задачи (1б: `search.py -b db/skills.db`,
3-5+ кандидатов; нашёл — ЗАГРУЗИ И СЛЕДУЙ; пусто — в веб), дебаг —
скиллы сначала (`skills_search.py "<симптом>" --top`), скачанный сторонний
скилл → СРАЗУ в quarantine-skills/, глубинное изучение директории — через
базу (build.py → --refresh → символы/граф), лестница поиска — code-search-ladder.

**2. Веб-ресёрч — первое действие.** Camoufox: поиск → первоисточники →
клики. «Подумал» без поиска = догадка. Ресёрч — ДО и в процессе, до конца
задачи. **Механика (детали — core.txt п.1, docs/canon/CAMOUFOX.md):**
норматив 10/30-50 источников, JS-страницы без подготовки, готовые ответы
индустрии раньше своих тестов, исследовательский цикл (RESEARCH → HYPOTHESIZE
→ EXPERIMENT → ANALYZE → LEARN, SIFT), гейт проверки в процессе (сверка
перед значимым шагом — факт не выдуман; одна ошибка в середине = каскад).

**3. План — для нетривиального.** Критерий готовности (как проверим), что
делаем, что сознательно НЕ делаем, риски. Мелочь — без плана.
Улучшение/рефакторинг — план ИЗ ДАННЫХ (метрики базы + граф CRG), не из
ощущений («улучшение без данных = догадка»).

**4. Действие.** Сначала индексация проекта (build.py, --refresh); поиск и
понимание кода — ЧЕРЕЗ базу, глубина — agent-lsp, ревью — code-review-graph.
Сначала смотри, что уже есть (scripts/, db-tools/, база) — не изобретай
велосипед (KISS/YAGNI). **Узкие специалисты — субагенты** (`agent/<имя>/`,
`@имя`; разноска — install_agents.py --all). **НЕТРИВИАЛЬНОЕ многошаговое —
fable-loop** (параллельные субагенты, intent gate, adversarial-проверка);
раздача — docs/canon/ORCHESTRATION.md (hard cap ≤5). **Кэш веб-ресёрча:**
fetch_page/batch_fetch кэшируются на сутки (~/.cache/aggg2-camoufox/cache.db);
web_search НЕ кэшируется. **Windows/CI** — сначала windows-encoding-fixes.
**Лимиты файлов** (код 500/1000, доки 300/500): упирается — РЕЖЬ.

**5. Проверка — обязательно.** Линтер + семгреп + тесты + CI (3 ОС) +
живьём, где можно. «Собралось» ≠ «работает».
**5а. Боевое крещение — ОБЯЗАТЕЛЬНО для нетривиального.** Стресс-тест
цифрами (скилл battle-test): замер ДО (N≥20-50, паузы от троттлинга) →
реверс КАЖДОГО отказа (наш баг/внешнее/артефакт) → фикс от причины →
перезамер тем же набором → «было X% → стало Y%» → урок в канон.
«Улучшение» без цифры — мнение; незамеряемо — честно «незамеряемо».
Тривиальное — без крещения. **Правки скиллов/канона/прошивки →
trigger/doc-eval** (eval_skill_triggers.py / eval_doc_triggers.py; пороги
recall ≥0.8, специфичность ≥0.7; CI — workflows trigger-eval). **Эвалы
меряют ЭФФЕКТ, не только триггер** (SkillsBench arXiv 2602.12670: скиллы
+16.2pp, но 16/84 задач — негативная дельта; сгенерированные скиллы ≈ 0
пользы — fable-domain: крещение обязательно; жизненный цикл: устаревший —
отзыв). **Chaos-инъекция отказов (ReliabilityBench arXiv 2601.06112):**
rate limit — самый разрушительный отказ; chaos-тесты ломают хуки/MCP и
проверяют фоллбэки (test_chaos_gates.py, test_red_team_gates.py). **Дорогой
дифф / спорное решение** — опция: multimodel_judge.py (3 ревьюера РАЗНЫХ
моделей + судья, НЕ для рутины). После «готово» на НЕТРИВИАЛЬНОЙ —
fable-judge (adversarial verification: отчёт = утверждения + перепрогон,
вердикт VERIFIED/REFUTED; поймал 12.08.2026 «зелёные проверки не проверяют
новую фичу»).

**6. Находки — в research.db.** После любого ресёрча/эксперимента/разбора:
`findings.py add` (что выбрали, почему, что отвергли, ссылки). Иначе знание
теряется. Продукт знания (пост/инструкция/разбор) — в `Wiki/` по протоколу
docs/canon/WIKI.md; журнал решений — research.db.

**7. Документирование.** Изменился код/поведение → CHANGELOG (что/где/
почему/было). Повторилась ошибка → правило в канон. Опыт → скилл.
**Связанные файлы — не по памяти:** правка канона/скрипта/дока →
`doc_deps.py check <файл>` (backlinks, зеркала, разнос).

**8. Отчёт.** Коротко, результат первым, честные оговорки. Строки
**«скиллы: N прочитано»** и **«semble: N запросов»** (на аудите/«что
улучшить»; 0 — честно «0») — обязательны (телеметрия: events.jsonl,
skill_loaded). Если задача в журнале — `tasks.py close <id> --result "..."`.
Если просят объяснить — как динозавру (аудитория → слои → пример → резюме
→ проверка). Визуально — структурно, не стеной.

## Гейты и переходы

- **Тривиально** — фазы 3-7 в свёрнутом виде: сделал → проверил одной
  проверкой → отчитался в двух фразах.
- **God-файл** — не расти: резать (механическая резка, docs/canon/FILE-SIZE.md).
- **Улучшение без данных** — фаза 1: метрики базы + CRG, потом предложение.
- **Не знаю / не уверен** — фаза 2 (ресёрч), не угадывать.
- **Ошибка 2 раза** — сменить метод, получить НОВЫЙ факт (лог, дамп,
  изоляция, история).
- **Необратимое / наружу / платно** — явное подтверждение пользователя.
- **Затык дольше 3 циклов** — остановиться, postmortem, правило в канон.

## Циклы вокруг

- **Цикл установки/обновления воркспейса:** setup.py (идемпотентный);
  обновление = git pull/свежий архив + setup.py; контроль —
  run_tests.sh --mirrors.
- **Цикл ревью:** дифф → CRG (impact/blast radius) → agent-lsp (глубина) →
  проверка dead-code ложных срабатываний → тесты.
- **Цикл ошибок:** грабля → причина → правило в канон → следующая задача
  идёт уже с этим правилом. Канон растёт только так — из реальных кейсов.
- **Цикл аудита (health-check):** refresh базы → метрики (топ файлов,
  --errors, --stats) → граф CRG (hubs/dead-code/gaps, ложные срабатывания —
  agent-lsp) → git-хотспоты (githist.py hotspots --top 10, паттерн
  CodeScene) → бэклог улучшений → выводы в research.db. По запросу
  «аудит / что улучшить» и периодически (docs/canon/DB-FIRST.md «Аудит»).
- **Цикл чекпоинта сессии:** длинная сессия (контекст >50% — sharp zone,
  паттерн compaction-prep) → чекпоинт-дельта в research.db
  (`findings.py add --tags checkpoint`) — формат индустрии (Codex handoff,
  Claude Code /compact, opencode compaction): **сделано**, **решения и
  ограничения**, **дальше**, **файлы**. Лимит ~200 слов, только non-obvious;
  дельта после прошлого чекпоинта. Авто-компакция харнеса — отдельно;
  этот ритуал — её ручная страховка в базе. **Пиннинг ядра при компакции
  (Governance Decay, arXiv 2606.22528):** компакция поднимает нарушения
  правил с 0% до 30% — прошивка переживает компакцию (proshivka.js
  re-inject ядра; Claude Code — ядро на каждый UserPromptSubmit). Это
  тренинг-фри Constraint Pinning из статьи — НЕ убирать. Конец сессии
  пишется детерминированно (SessionEnd-хук → sessions.jsonl + флаг qa_gap).
  **Не режь ядро ради «экономии»:** стабильный префикс на каждый ход =
  промпт-кэш ~90% (замер galileo.ai 2026: харнесс с бОльшим префиксом
  в 3× дешевле за ход — 92.7% кэша против 23.8%; «меньше токенов =
  дешевле» больше неверно). Токен-аудит 19.08: дубли префикса (core ↔
  AGENTS ↔ монолит, overlap 51-63%) — НЕ ядро, а копии: их режем,
  constraint pinning остаётся (research.db id=1017).
