# Хирургическая правка JSONC: сохранить комментарии и чужое

Паттерн индустрии (Microsoft `node-jsonc-parser`, им VS Code правит settings.json): конфиг правится **текстовыми edits по оффсетам** — заменяется только нужный участок, остальное (комментарии, чужие записи, отступы, порядок ключей) нетронуто. НЕ `json.dump` — стирает комментарии и переформатирует всё.

Проверено на багах AGGG2.0: частичная установка MCP вычищала чужие core-серверы, install_mcp.py терял комментарии opencode.jsonc. Реализация: `scripts/jsonc_edit.py` (используется `install_mcp.py` и `install_proshivka.py`): `_jsonc_key_map`, `_edit_mcp_section`, `_server_value`, `_server_block`.

## Когда это нужно

- Скрипт/установщик пишет в конфиг с **комментариями** (`//`, `/* */`) — нельзя терять.
- В конфиге есть **чужие записи** (ручные/других скриптов) — не трогать при доставке своего.
- Повторные запуски **идемпотентны** (два прогона = один файл).

## Как работает jsonc-parser (VS Code)

1. `parseTree(text)` — AST с `offset`/`length` в ИСХОДНОМ тексте.
2. `setProperty`/`removeProperty` → `Edit[]` `{offset, length, content}`:
   - **обновление:** заменяется ТОЛЬКО значение; ключ, запятые, комментарии рядом не трогаются;
   - **удаление:** не первый элемент — от конца предыдущей ноды (забирает запятую); первый — от `parent.offset + 1`, при наличии следующего — до его начала;
   - **вставка:** после последней ноды `{offset: конец, length: 0, content: ',' + new}`; в пустой объект — `parent.offset + 1`.
3. `applyEdits` применяет правки; `withFormatting` форматирует только диапазон правки, `keepLines: false` — остальной файл не переформатируется.

## Наша реализация (тот же паттерн, без зависимостей)

| Функция | Что делает |
|---|---|
| `_jsonc_key_map(text, want_depth, base, limit)` | сканер ключей с `(key_start, value_start, value_end)`; игнорирует строки/`//`/`/* */`; считает скобки; возвращает `root_end` |
| `_skip_string` / `_skip_comments` / `_skip_value` | строки с экранированием, комментарии, парные скобки |
| `_server_value` / `_server_block` | форматирование значения/записи, отступы как `json.dumps(indent=2)` |
| `_edit_mcp_section(raw, servers, known, clean_stale)` | правки в координатах исходника, применяются с конца; чужие не трогает; `clean_stale=True` чистит устаревших известных |
| `_parse_jsonc(text)` | JSONC-текст → объект (вынесен из `load_jsonc`) |

Ключевые правила:

- **Правки в координатах исходного текста, применяются с конца** (по убыванию `start`) — иначе первая правка сдвигает оффсеты остальных.
- **Чужие записи не удаляются при частичной установке**; `clean_stale = not args.server` — чистка устаревших только при полной (без фильтра `--server`).
- **Удаление с запятой:** не первый элемент — от запятой ПРЕДЫДУЩЕГО до конца значения (ws после не забирать); первый — от ключа, забрав ws и запятую после.
- **Вставка одной правкой** перед закрывающей скобкой секции: ws-хвост секции → `,\n` + блоки + отступ секции (исходная `}` остаётся).
- **Вставка vs обновление:** вставка — полная запись `"name": {...}` с отступом ключа; обновление — только значение `{...}` (без отступа — продолжает строку ключа).

## Грабли (собраны на практике)

1. **Оффсеты после правки устаревают** — старые `mcp_vs/mcp_ve` = IndexError/мусор; все правки в координатах исходника, применение с конца.
2. **`_line_indent` возвращал строку до позиции, не ведущие пробелы** → отступы съезжали. Фикс: `ws[:len(ws) - len(ws.lstrip())]`, передавать `key_start`, не `value_start`.
3. **Блок вставки терял имя ключа** — `{...}` без `"name": `. Фикс: `_server_block` для вставки, `_server_value` для обновления.
4. **Склейка строк при удалении** — `}"my-server"`. Фикс: при удалении не-первого элемента НЕ забирать ws после значения.
5. **Дубль `}`** — вставка с `}` + исходная `}` секции = `}}`. Фикс: заменять ws-хвост секции, `}` не добавлять.
6. **Запятая при создании секции** — `"," if top (есть ключи) else "\n"`.
7. **Удаление устаревших при частичной установке** — `--server X` фильтрует только добавление, удаление шло по всем. Фикс: `clean_stale` только для полной.
8. **`load_jsonc` ждал путь, не текст** — FileNotFoundError в тестах. Фикс: вынести `_parse_jsonc(text)`.
9. **`# noqa: SIM115`** — нужен для `open(...).read()`, лишний для `with open` (RUF100). Проверять, куда ставишь.

## Чеклист перед правкой JSONC-конфига скриптом

- [ ] правки по оффсетам исходника, применяются с конца
- [ ] чужие записи не трогаются при частичной; чистка устаревших — только полная
- [ ] удаление: запятая предыдущего/следующего учтена; вставка: имя ключа, отступ как у соседей, без дубля `}`
- [ ] комментарии вне правимых блоков сохранены (тест на `//`); идемпотентность; валидация `_parse_jsonc`
- [ ] юнит-тесты на временных файлах (реальные конфиги не трогать)

## When NOT to use

- Чистый JSON без комментариев/чужих записей — `json.load` + `json.dump`.
- Разовое добавление одного ключа — переписать проще (YAGNI).
- TOML/YAML — свои правила (TOML в install_mcp.py — построчная правка секций).
- «Что сломалось после правки конфига» — сначала `debug-incident-protocol`.
