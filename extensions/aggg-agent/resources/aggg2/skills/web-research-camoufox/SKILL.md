# Web research: Camoufox по максимуму

Первоисточник: `docs/canon/CAMOUFOX.md`. Норматив (≥10 / 30-50), лестница веб-инструментов, фоллбэк, JS-страницы, SIFT, две дорожки — ядро: core.txt п.1.

## Workflow (порядок применения)

1. **База сначала.** «Мы это разбирали» → `findings.py search`/`search.py` + --knowledge/--internet: ответ уже есть — **НЕ ходи в веб** (ядро: core.txt п.1-2). Браузер — только за НОВЫМ знанием.
2. **Стандартный ресёрч.** `web_search("тема")` 3-5 запросов с РАЗНЫХ сторон → `batch_fetch` лучших 10+ URL (первоисточники, не пересказы) → сверить: факт в одном — подтверждение в другом → `findings.py add`.
3. **Глубина — от норматива вверх.** Справка — минимум 10 источников. Решение/выбор — ГЛУБОКИЙ: 5-10 web_search параллельно (карта темы) → кластеры → глубина по 1-2 лучшим из каждого (30-50 суммарно). «Скользить» = решение из догадок.
4. **Исследовательский цикл (спираль, не круг).** RESEARCH → HYPOTHESIZE (если X, то Y, потому что Z) → EXPERIMENT (реальное действие) → ANALYZE → LEARN (выводы в research.db). Затык/плато → ВЕРНУТЬСЯ в RESEARCH (другой подвод, смежная тема), не долбить те же гипотезы.
5. **Учись у других.** Эталонные репо (README → тесты → ранние коммиты → git log: частые правки = ядро). Одна задача в 2-3 проектах (разница подходов = урок). PR/Issues/ADR/RFC (отвергнутое = как думают).
6. **Выбирай стандарт измерением.** Сколько прод-проектов используют (исходники, не пересказы); «X vs Y», «почему перешли»; офиц. доки > личные статьи; свежесть важнее древности. Survivor bias: популярный плохой код — НЕ стандарт. Итог: паттерн + почему победил + что отвергнуто.
7. **После ресёрча — ОБЯЗАТЕЛЬНО.** `findings.py add` (--source на отчёт, --related на связанные); глубокий — отчёт в `docs/research/<дата>-<тема>.md`; менялся код — пересобрать базу.

## Инструменты (8)

| Инструмент | Что делает | Когда |
|---|---|---|
| `ping` | проверка связи | перед длинной серией |
| `web_search(query, pages=1)` | DDG; `pages>1` — пагинация | старт любого ресёрча |
| `fetch_page(url, article_only=False)` | текст без HTML-мусора; article_only — статья (Trafilatura) | читать статью/доку |
| `batch_fetch(urls, article_only=False)` | НЕСКОЛЬКО URL в одном браузере | глубокий: 30-50 одним вызовом |
| `browser_navigate` | текст + первые ссылки | ориентироваться |
| `browser_click` | клик по селектору/тексту | «дальше», табы, кнопки |
| `browser_type` | ввод в поле | формы поиска |
| `extract_links` | собрать ссылки (фильтр) | ссылки на скачивание/исходники |

**Кэш (проверять!):** `fetch_page`/`batch_fetch` кэшируют текст на сутки (`~/.cache/aggg2-camoufox/cache.db`) — повторный fetch мгновенный. web_search НЕ кэшируется. Глубокий: `web_search(pages=2-3)` → `batch_fetch(max_chars=2000-3000, article_only=True)` → полный текст из кэша точечно. Замер: 16 URL — 83с, 40 URL ≈ 3.5 мин.

## Оркестрация большого ресёрча (субагенты)

1. **DECOMPOSE** — 5-15 под-вопросов, план в отчёт.
2. **СУБАГЕНТЫ** — на каждый под-вопрос ПАРАЛЛЕЛЬНО («web_search → fetch первоисточников → вывод с URL; верни компактное резюме»).
3. **СИНТЕЗ** — сверить противоречия, каждое утверждение с URL. 4. **ОТЧЁТ** — docs/research/ + findings.py add.

Правила: не дробить мелкое (справка — 1, сравнение — 2-3, обзор индустрии — 5-15); субагент узкий; SIFT делает родитель, не субагент.

## Грабли

- `fetch_page` обрезает длинные статьи по `max_chars` (default 6000) — поднимать `max_chars=12000+`.
- Сайты падают/таймаутят — переформулировать, зеркало (pkg.go.dev вместо github), web_search. Не застревать.
- «Ничего не нашёл» — почти всегда формулировка: короче, без спецсимволов (дефис ломает FTS — «agent lsp»), латиницей.
- Живой воркер (serve): браузер держится между вызовами с 08.2026 — первый вызов платит старт. Для 30-50 URL — `batch_fetch` (один старт на все).
- Пагинация DDG — только POST-форма Next: GET `&s=` игнорируется; `web_search(pages=N)` делает сама.
- Доступность сайтов — через браузер, не curl (TLS-фингерпринт, JS, капчи → ложные 403; проверено: hdrezka curl — 403, браузер — «ERROR 105»).
- «Думать» = тоже ресёрч: выбор — сначала Camoufox, потом анализ.
- Сомневаешься «хватит ли источников» → брать БОЛЬШЕ: нехватка = догадка, переизбыток = токены.
