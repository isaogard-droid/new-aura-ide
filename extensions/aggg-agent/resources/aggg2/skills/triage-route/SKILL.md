# Triage & route

Первое, что делает реверс-инженер: 4 вопроса и маршрут. Не читать все скиллы сразу — только маршрут (паттерн r0crawl_skills).

## 4 вопроса (всегда)

1. **Цель:** сайт / API / бандл JS / расширение / бинарник / протокол / чёрный ящик?
2. **Действие:** запуск, логин, поиск, запрос, шифрование, валидация, обмен?
3. **Материал есть:** файл, URL, HAR/PCAP, лог, скриншот, дамп, исходник — или только описание?
4. **Результат нужен:** объяснить поведение, точка входа, перехват/подмена, восстановить запрос, отчёт?

Материала нет → план сбора артефактов, не «анализ» невидимой цели.

## Маршрутизация (сигнал → грузить первым)

| Сигнал (цель/материал) | Скилл |
|---|---|
| Сайт, веб-приложение, «как это работает» | `black-box-to-blueprint` |
| API, «что за запросы», контракт | `black-box-to-blueprint` → `code-recovery` |
| Минифицированный JS, бандл, обфускация | `js-deobfuscation` → `code-recovery` |
| Подпись/токен/шифрованный параметр (x-s, x-bogus, _abck...) | `web-signature-analysis` |
| Бинарное тело (protobuf/grpc/msgpack), PCAP, WebSocket | `protocol-reconstruction` |
| «Перехватить/подменить/замокать» | `redirect-intercept` |
| Расширение, content script | `black-box-to-blueprint` → `redirect-intercept` |
| Логи, ошибки, «почему не работает» | `black-box-to-blueprint` (сначала своё vs чужое) |
| Бинарник, протокол, дамп | `black-box-to-blueprint` + внешние инструменты |
| Нативный бинарник (EXE/ELF/Mach-O), .so/.dll, крак, малварь | `binary-reversing` (триаж → статика → динамика → патч) |
| Файл неизвестного формата, прошивка, сохранение | `file-format-analysis` (сигнатура → структура → извлечение) |
| Игра: Unity/Unreal/Cocos, ассеты, механики | `game-reversing` (движок → код → ресурсы → патч) |
| Мобильное (APK/IPA), Frida, TLS-пиннинг | `mobile-reversing` (декомпиляция → динамика → трафик) |
| Зашифровано: трафик/файл/поле, подпись, ключи | `crypto-network-analysis` (распознать → ключ → дешифровка) |
| Восстановить функцию/алгоритм | `code-recovery` |

Сценарий = маршрут + шаги + критерий готовности.

## Правила маршрута

- **Порядок:** понять (blueprint) → перенаправить (intercept) → восстановить (recovery). Перехватывать непонятое нельзя.
- **Один маршрут за раз.** Неизвестен тип цели — начинать с `black-box-to-blueprint`. Материала нет — план сбора.
- После разбора: находки в research.db (`findings.py add`), lineage обязателен.

## Результат триажа

«Цель: <тип>. Материал: <что есть>. Маршрут: <скилл(ы)>. Результат: <что получим>». Затем грузить первый скилл маршрута.

- **Дальше:** реверс-скиллы агента (reverser), `skill-search`
