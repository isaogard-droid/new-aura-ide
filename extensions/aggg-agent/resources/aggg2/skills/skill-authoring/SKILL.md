# Как правильно создавать скиллы и плагины

По спецификации Agent Skills (agentskills.io) + практике (`gpt-cli`, `gta4-wine-fix`).

## 1. Frontmatter (обязательные поля)

```markdown
---
name: my-skill
description: Use when [триггеры/симптомы/контексты]. [что делает + когда применять]
---
```
- `name` — ОБЯЗАТЕЛЬНО, 1–64 симв., `^[a-z0-9]+(-[a-z0-9]+)*$`, без `--`. **Должен совпадать с именем папки**.
- `description` — ОБЯЗАТЕЛЬНО, 1–1024 симв.: «что делает + когда», ключевые слова. НЕ сводка рабочего процесса (агент следует description и пропускает тело).
- `license` опционально; `compatibility` 1–500 симв. (только окружение); `metadata` строка→строка; `allowed-tools` экспериментально.
- opencode использует тот же frontmatter, неизвестные поля игнорирует. Валидация: `skills-ref validate ./my-skill`.
- ⚠️ `description` — ВСЕГДА в одинарных кавычках `'...'`: plain-YAML с `: ` ломает парсинг — reasonix молча теряет описание («has no description», скилл не в индексе). Проверено 18.08. Не доверяй «домашним» конвенциям — противоречат спецификации.

## 2. Структура каталога

```
skill-name/
├── SKILL.md            # обязателен
├── scripts/            # опционально: исполняемые скрипты
├── references/         # опционально: детали, «читай при X»
├── assets/             # опционально
└── любые другие файлы/папки — разрешены
```
- Discovery (opencode): `~/.config/opencode/skills/<name>/SKILL.md`, в проекте `.opencode/skills/`; также `.claude/skills/`, `.agents/skills/`. Reasonix: `<workspace>/.reasonix/skills/`.
- Ссылки из SKILL.md — **относительными путями от корня скилла** (opencode резолвит сам; `$SKILL_DIR` в opencode НЕТ).
- Progressive disclosure: SKILL.md < ~500 строк / ~5000 токенов; детали — в `references/` с указателем «читай, когда случится X».

## 3. Бандлинг скриптов (scripts/)

1. **Сначала готовый инструмент**: `npx pkg@version`, `uvx`, `pipx`, `bunx`, `deno run` — своё только когда готового нет.
2. Скрипт — **self-contained**; зависимости в SKILL.md или `compatibility`.
3. **Зависимость — В ПАПКУ скилла** (node ищет node_modules от пути скрипта): playwright → `cd <скилл> && npm install playwright`. Иначе `Cannot find module`.
4. **Агентно-безопасный дизайн**: без интерактивных промптов (Read-Host/readline-blocking — агент зависнет на TTY; ввод только аргументами); `--help` с usage; результат в stdout (JSON/CSV/текст), диагностика в stderr; идемпотентность, `--dry-run` для разрушительных, различимые коды выхода; предсказуемый размер вывода (~10–30К символов).

## 4. Лучшие практики и антипаттерны

**Единый источник правды:** одна каноническая версия; несколько мест — зеркала: правка канона → синхронизация всех + `md5sum`.

**Делать:** маленький композируемый скилл (одна связная задача); description императивный «Используй при …» с триггерами, без first/second person («I can help…» ломает распознавание); добавлять то, чего агент не знает, выкидывать то, что умеет; `Gotchas` — самый ценный контент; чеклисты для многошаговых; дефолты, не меню; процедуры, не декларации; калибровать детализацию под хрупкость; явные `Success criteria` и `Failure modes`.

**Не делать:** код в SKILL.md — в `scripts/`; workflow в `description`; много равнозначных вариантов без дефолта; generic-контент без предметных знаний; оверфит description под eval-запрос.

**Валидация:** прогон с-скиллом против базлайна (без скилла); после правки — реальный запуск скрипта из папки скилла.

**Веб-серч перед созданием (обязательный шаг):** research по официальным источникам (agentskills.io, доки opencode/Reasonix) — лимиты полей, пути, discovery; каждый факт с URL, непроверенное помечать. Форматы меняются между версиями.

### 4.1 Триггер-эвалы и гейт на правку description (индустрия 2026)

- **Description — единственный триггерный рычаг** (в контексте только name+description). Правка = breaking change → только с прогоном эвала.
- **Eval-набор:** 10-20 промптов (OpenAI) / 20-50 (Anthropic) — should + should-not с near-miss негативами; прогон 3 раза: trigger rate ≥ 0.5, recall ≥ 0.7 (UiPath gate), precision по негативам.
- **CI-гейт:** усреднение 3+ прогонов против baseline; полный набор на merge/nightly, лёгкий на PR; правка description без эвала — ревью отклоняет.
- **SkillEval** (arXiv 2608.06891): качество = applicability + content quality + execution guidance + robustness (Pearson 0.78-0.79 с пользой).
- **Skill lift:** парный прогон with/without (SkillsBench: curated +16.6pp; self-generated −1.3pp — кураторство человеком обязательно); дёшево: 3-5 задач + детерминированные чеки + LLM-as-judge для стиля.
- **Жизненный цикл:** устаревший/вредный скилл — ОТЗЫВ (retirement): не помог по замерам или дублирует другой → архив/удаление + запись решения в research.db.

## 5. Паттерны из нашей практики

| Паттерн | Правило | Гард |
|---|---|---|
| Две копии ≠ два источника правды | `.reasonix/skills` и `.config/opencode/skills` — зеркала (оба места всегда) | `cp -r` + md5 |
| Имя папки = name | Несовпадение ломает discovery | `name` строго равен имени папки |
| Без «Этапы (handoff)» | Цепочки скиллов разъезжаются | секция ОБЯЗАТЕЛЬНА: «Вход из:» + «Дальше:» |
| Проверка запуском | «Написан» ≠ «работает из папки скилла» | `node scripts/x.js --help` из корня скилла |
| Библиотека vs плагин | Готовый движок — из npx/пакета; свой — обвязка | «npx → адаптер → свой код» |
