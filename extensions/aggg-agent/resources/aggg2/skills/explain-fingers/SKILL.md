# Объяснять на пальцах

Режим для обычного человека по ту сторону экрана: цель — чтобы стало ПОНЯТНО, не «узнал умные слова». Родился из фидбека владельца: объяснение мультимодельного судейства через консилиум врачей понравилось больше всех стилей.

## Когда использовать

- «объясни на пальцах», «как динозавру», «объясни просто», «ELI5», «не понимаю»;
- собеседник теряется: переспрашивает, просит «ещё раз», тема новая;
- сложная абстракция для человека без контекста.

НЕ использовать: технический разбор для разработчика, ответ-факт «да/нет», когда явно просили коротко.

## Метод (5 шагов, по порядку)

1. **Аналогия первой строкой.** Незнакомое — через знакомое из быта: «консилиум врачей», «склад и доставщики», «ОТК на заводе». Одна, максимум две.
2. **Кто есть кто.** Действующие лица в терминах аналогии: «три врача из разных школ», «главврач».
3. **Шаги по одному.** 3-5 шагов, каждый — одно действие; не больше одного термина на шаг, жаргон — с расшифровкой.
4. **Живой пример.** Короткий, из реальной жизни, не абстрактный.
5. **Резюме одной фразой + проверка.** «Одной фразой: ...» + обязательный вопрос: «Понятно? Что осталось мутным?» — и добить именно это.

## Правила

- **Быт, а не техника.** Врач, завод, кухня, магазин, суд. Не «как в микросервисах».
- **Одна аналогия**; вторая — только если первая не зашла. **Никакого «очевидно же»** — это и есть причина вопроса.
- **Структура видимая:** таблицы для сравнений, списки для шагов, bold для главного.
- **Проверка понимания — всегда:** «Понятно? Что осталось мутным?», не «вопросы?».
- **«Ещё проще»** — упростить СИЛЬНЕЕ (короче, знакомее аналогия), не повторять то же.
- **Честность:** не знаешь — «нужно проверить», не выдумывать в угоду простоте.

## Пример-образец (как это выглядит)

Вопрос: «как работает мультимодельный судья?»

> Представь завод. Ты сделал деталь. **Три контролёра из разных цехов** проверяют её по отдельности, друг друга не видят. Каждый пишет заключение. **Начальник ОТК** читает три заключения: видит расхождения — переспрашивает каждого и выносит одно решение: «годна» или «вот эти три дефекта исправить».
>
> Контролёры ничего не делают — только проверяют. Код пишешь ты.
>
> Одной фразой: **три независимых проверяльщика + главный, который сводит их мнения в одно решение.**
>
> Понятно? Что осталось мутным?

## Success criteria

- Собеседник может пересказать суть своими словами; в ответе есть аналогия, шаги, пример, резюме, вопрос в конце; ноль терминов без расшифровки.

## Failure modes

- «Всё равно не понял» → упростить сильнее, спросить, какой шаг мутный.
- Обиделся на «детский» тон → просто ≠ сюсюкать; аналогия рабочая.
- Аналогия уводит → вернуться к сути: «в реальности это значит...».

## Gotchas

- Просили технически — «на пальцах» не нужно; спросить уровень (вопрос дешевле переделки).
- Таблица — для сравнений; ячейки 5-10 слов.
- Проверка — инструмент: «понятно» без энтузиазма → предложить пересказать.
