# system-feedback

У любого действия есть видимый результат — либо это дефект. Каждое состояние экрана проектируется заранее. Обратная связь — часть поведения: без неё человек не понимает, сработало ли действие, и повторяет его (дубль/ошибка).

## Когда подключать

Любое действие (сохранение/копирование/удаление/отправка/загрузка/синхронизация), экран с загрузкой или возможным падением, «странный» интерфейс. Не для полировки/тайминга/эстетики.

## Ключевые положения

- **Тишина после действия = поломка**, даже если внутри успешно.
- **Ответ виден там, куда смотрит человек**, не где удобно разработчику.
- **Молчание = «не сработало»** — человек жмёт ещё раз.
- **Ошибка говорит, что делать**, а не только что случилось.
- **Пусто/загрузка/ошибка — полноценные состояния**, как и наполненное.
- **Необратимое — подтвердить, обратимое — дать отмену.** Подтверждения на каждый чих перестают читать.

## Как работать

### 1. По каждому действию: откуда человек узнает об успехе?

«Никак» / «данные обновятся сами» = обратной связи нет.

| Способ | Когда уместен |
|---|---|
| Изменение самого элемента | результат виден в нём (галочка, подпись) |
| Сообщение возле действия | результат не виден на экране (скопировано) |
| Признак процесса | операция длится дольше мгновения |
| Отмена | действие обратимо и могло быть случайным |

Выбор по близости: чем мельче действие, тем ближе ответ. Тост в углу на кнопку в списке никто не увидит.

### 2. Долгие операции показывают, что идут

Заметная задержка (от сотен мс) → признак работы. >2с и прогресс можно честно посчитать — показывать его; нельзя — индикатор + короткое пояснение.

### 3. Состояния экрана — все сразу

- **пусто** — приглашение к действию («Начни с поля внизу», не «Заметок нет»)
- **загрузка** — данных нет, но появятся
- **ошибка** — что случилось и что делать
- **основное** — данные на месте
- **край** — много элементов, длинное имя, нет прав

### 4. Ошибки по формуле (3 части по порядку)

1. **Что произошло** — без кодов и терминов
2. **Что делать** — конкретный шаг, не «попробуйте позже»
3. **Что дальше**, если известно (сохранено, повтор через минуту)

Плохо: «Ошибка синхронизации (код 42)». Хорошо: «Не удалось синхронизировать — нет сети. Изменения сохранены локально и уйдут, когда соединение появится».

### 5. Подтверждение только для необратимого

Отмена почти всегда лучше: не тормозит путь, спасает от случайности. Подтверждение — когда отменить нельзя, и называть последствие («будет удалено 12 записей»), не «вы уверены?».

## Самопроверка

По каждому нажимаемому элементу: что произойдёт; как я узнаю; что при неудаче; можно ли отменить. «Никак» на второй вопрос — дефект.
