# loop — режим повторяющихся витков

Виток за витком: полный цикл → находки и чекпоинт в research.db → следующий виток с НОВЫМ углом. Стоп — только по явным критериям.

## Формат вызова

```text
/loop [N] [M] [промт]
```
- N — число витков; не задан → **5**. M — лимит минут (`m`/`h`); оба заданы → стоп по первому. Промт не задан → **продолжение с последнего чекпоинта**.
- Примеры: `/loop 10 30m <задача>` · `/loop 99 6666 <улучшения>` · `/loop улучши CI` · `/loop`

## Когда использовать / НЕ использовать

**Использовать:** явная просьба о цикле/итерациях; серия улучшений, где шаг зависит от результата предыдущего. **НЕ:** одиночная задача — `task-cycle`; параллельный разбор одной задачи — `fable-loop`; тривиальная просьба.

## Workflow

**0. Инициализация (раз):** `tasks.py add "<промт>" --tags loop` → стартовый чекпоинт → `date +%s` (лимит M) → критерий готовности (зелёные тесты/N находок/файл); нельзя сформулировать — уточнить у пользователя.

**1. Виток (повторяется):**
1. **Угол витка:** одна фраза — чем отличается от предыдущего (гипотеза/источник/инструмент). Повтор прошлого витка запрещён.
2. **База:** `findings.py search` по теме — не спорить с собственными выводами.
3. **Действие:** ресёрч → правки/эксперимент → **проверка** (линтер/тесты/живьём; «собралось» ≠ «работает»).
4. **Находки:** `findings.py add` — выбрал/отверг, ссылки. Витки без находок = потерянные.
5. **Чекпоинт-дельта:** `findings.py add --tags "loop checkpoint"` (формат ниже).
6. **Сводка юзеру:** 1-2 строки — виток X/N, что сделано, что дальше.

**2. Переход:** прогресс есть → развивать; нет 2 витка подряд → **сменить угол** (CYCLE.md: ошибка 2 раза = сменить метод; прогресс — по метрике, не по ощущению). Перед стартом сверка: витков ≥ N? минут ≥ M? критерий достигнут И проверен? Да → фаза 3.

**3. Стоп и финал:** `tasks.py close <id> --result "итог"` → отчёт (сделано/осталось/как продолжить: `/loop`) → стоп всегда с названной причиной.

## Детектор прогресса и ретрай-политика

- **Fingerprint повторов:** хэш (шаг+результат) витка; 2 одинаковых без новой информации = стоп-критерий → сменить угол.
- **Ретрай по классам:** validation/auth/перманентные → STOP; 429/timeout → 2-3 ретрая с backoff+jitter; safety/необратимое → подтверждение владельца; остальное — 1 ретрай.
- **Бюджеты:** витки/минуты + токен-гигиена + деньги на дорогие операции — выход за любой = стоп с причиной.

## Чекпоинт-формат (research.db, --tags "loop checkpoint")

`loop: виток X/N | сделано: <что> | метрика: <N файлов/строк/тестов — прогресс механически> | решения: <выбрал/отверг> | дальше: <угол> | файлы: <что>` — ~110 слов. `findings.py search loop` восстанавливает контекст после перезапуска сессии.

## Success criteria

N витков (или M минут), каждый с находкой и чекпоинтом (`findings.py search loop` ≥ N+1); или раньше — критерий достигнут И проверен. Каждый виток отличается от предыдущего; стоп — с причиной, задача закрыта.

## Failure modes

- Повторяет виток → смена угла после 2 витков без прогресса — применять, не обсуждать.
- Scope creep → виток — ровно одна цель, чужие правки — красный флаг.
- Контекст на исходе (>50-60%) → не начинать виток: чекпоинт + «скажи /loop — продолжу».
- Юзер не видит прогресса → сводка 1-2 строки после КАЖДОГО витка — обязательна.
- Остановился без причины / решения не записаны → стоп только по критериям фазы 3, каждый виток обязан оставить находку.

## Gotchas

- Счётчик витков — ЯВНО в чекпоинте (виток X/N); минуты — по `date +%s`.
- Дорогие/необратимые/наружу — подтверждение пользователя даже внутри цикла (CYCLE.md).
- «Критерий достигнут» — только после проверки проверкой (fable-judge); маленький проверенный шаг > большого непроверенного.
- Возобновление (`/loop` без аргументов) — не повторять side-эффекты сделанного: чекпоинт восстанавливает контекст, не переигрывает действия.
- Токен-гигиена: дорогие операции (судья, дип-ресёрч 30+, эвалы) — не каждый виток; чередовать дёшево/дорого.
- `/loop 99 6666` — большой автономный режим: чекпоинты критичны.
