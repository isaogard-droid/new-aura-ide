Шкала не выдумывается — она снимается с кода. Шесть шагов, каждый из которых
появился из конкретной ошибки. Плюс отдельно — типографика.

## Содержание

- замерить существующее
- сжать значения по замеру
- посчитать цену до правки
- разделить значения по природе
- пометить исключения
- проверить систему на ней самой
- отдельно проверить типографику

---

## 1. Сначала — статистика

Шкалу не придумывают: её достают из проекта. Первый шаг — посчитать, какие
значения уже используются и как часто.

```bash
# частота значений по типу
grep -rhoE 'padding\([0-9]+|cornerRadius: [0-9]+|spacing: [0-9]+' src/ \
  | grep -oE '[0-9]+$' | sort -n | uniq -c | sort -rn
```

Как читать результат:

- **частые значения** — живые ступени, они уже работают;
- **редкие рядом с частыми** — шум, кандидаты на сжатие;
- **редкие крупные одиночки** — скорее всего не из этой шкалы (см. шаг 4).

Шкала 4/8/16/32 «для красоты» сдвинет половину работающего интерфейса без
причины. Замер занимает минуты и обосновывает каждую ступень.

**Предотвращает:** систему на догадке, которая расходится с реальностью
и переделывается целиком.

---

## 2. Сжатие по частоте

Промежуточные значения убираются, но каждое сначала проверяется по частоте.

Значение «между 16 и 24» может оказаться третьим по частоте во всём проекте.
Это не шум, а отдельное решение — срезать его нельзя.

**Правило:** ступень остаётся, если встречается заметно чаще соседнего шума.
Порог зависит от проекта, но лидеры обычно отрываются в разы.

**Предотвращает:** срезанную живую ступень, из-за которой десятки мест сдвинутся
без причины.

---

## 3. Цена до правки

Перед массовой заменой — расчёт: сколько мест меняется, на сколько, где самые
крупные сдвиги.

```
# псевдокод расчёта
для каждого найденного значения:
    ближайшая ступень шкалы
    сдвиг = |ступень - значение|
сгруппировать по величине сдвига
```

Расчёт вскрывает невидимое: слепое применение правила ломает часть случаев,
«однотипные» значения на деле разной природы, сама шкала дырявая.

**Предотвращает:** массовую замену, ломающую вёрстку там, где значение было
осмысленным.

---

## 4. Природа важнее вида

Одинаковые на вид числа часто имеют разный источник:

| Природа | Пример | Куда |
|---|---|---|
| Выведено из системы | отступ внутри карточки | в шкалу |
| Производное от другого элемента | «ширина иконки + зазор» для выравнивания | в именованную константу рядом с источником |
| Уникально для места | позиционирование всплывающего окна, поля вокруг изображения | оставить как есть |

Производные величины — самые коварные: выглядят как обычные отступы, но
привязаны к размеру соседнего элемента. Оставленные числом, они разъедутся,
когда элемент изменится.

**Предотвращает:** натягивание шкалы на то, что ей не принадлежит, — портит
и шкалу, и место.

---

## 5. Исключения — с объяснением

Каждое значение, не приведённое к системе, несёт объяснение рядом:

```
// 92 — не токен: позиционирование окна от верха экрана.
```

**Молча оставленное отклонение неотличимо от забытого.** Следующий проход либо
«доделает» его и сломает, либо будет бояться трогать.

**Обратная сторона:** если объяснение не пишется — отклонение не обосновано,
его надо приводить к системе. Требование написать причину работает как фильтр.

---

## 6. Проверить систему на себе

После введения — прогнать проверку по коду самой системы.

Дизайн-система, не пользующаяся своими токенами; линтер с исключением на
собственный код; конвенция, нарушенная в её же описании — подрывают правило
целиком. Дальше на него никто не ссылается.

Единственное законное исключение: место, где значения **определяются**. Числа
где-то должны лежать физически.

---

## Отдельно про типографику

Если платформа даёт семантические стили текста (не пункты, а роли) — строить
шкалу на них, а не на числах. Причина не стилистическая: семантические стили
следуют системным настройкам размера текста, числовые — нет. Приложение с
захардкоженными кеглями игнорирует настройки доступности пользователя.

**Но:** фактические размеры надо **замерить**, а не взять из документации.
Платформы схлопывают соседние ступени по-разному, и две «разные» роли могут
оказаться одним кеглем. Это надо знать до того, как рисовать макет.
