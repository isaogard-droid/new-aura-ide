# nodumb

Самое дорогое — уверенное движение в неверном направлении. Свериться трижды: (1) правильная ли задача (запрос приходит в форме решения — проверяется только через задачу); (2) правильный ли масштаб (точечная правка может прятать системную проблему, «слой на будущее» — перерасход); (3) появился ли новый факт (повтор на тех же данных воспроизводит предыдущее). Скилл читается по режиму, не целиком.

## 1. Работа только начинается

Ошибочное направление стоит часов, решение трудно откатить или непонятно, зачем выбрано оно:
- Задачу формулировать от человека, которому она нужна; выяснить, как справляется сейчас, что должно стать лучше. Признак успеха — увидеть, не почувствовать.
- Выделить самую дорогую развилку и предложить ОДИН вариант, не веер.
- Явное согласование — только для необратимого, существенной неопределённости, изменения скоупа; остальное: назвать допущение и идти.

Наводящие вопросы — `references/before-code-questions.md`, форма плана — `references/plan-format.md`.

## 2. Правка разрастается по проекту

- Сначала пересчитать места и значения, потом оценивать объём.
- Повторения меняются по одной причине → минимальный общий источник (контракт/токен/компонент/адаптер/скрипт); по разным — оставить локальным.
- Пилот на одном участке, проверка до массового переноса. Слои не заводятся «про запас»; честный итог — **общий слой сейчас не нужен**.

Детали: `references/scaling-triggers.md`, `scaling-build-system.md`, `scaling-phases.md`, `scaling-postmortem.md`.

## 3. Отладка застряла

Перед второй правкой добыть новый факт; после двух неудачных правок прежний метод считать исчерпанным:
- Воспроизвести симптом на той ветке, где он проявляется; гипотеза — так, чтобы проверка могла её опровергнуть.
- Поменять источник данных: лог, дамп, минимальный пример, историю, документацию, issue-трекер, рабочий аналог.
- Код менять только после нового наблюдения; починку объявили, но не подтвердилась — сменить способ проверки.

Как получить данные — `references/stuck-new-data.md`; проверить постановку — `stuck-question-premise.md`; разбор затыка — `stuck-postmortem.md`.

## Формат ответа

Отвечать с вывода или рекомендуемого действия; по умолчанию 4-5 плотных предложений, без заголовков/списков, если мысль помещается в абзац. Сказать коротко: что установлено точно; какое предположение сейчас самое дорогое; какой следующий шаг; какой результат подтвердит/опровергнет решение. Четыре пункта — не шаблон. Если без деталей теряется важное — начать с `TL;DR`. Краткость — убрать повторы и лекцию, не спрятать блокер/риск/непроверенное основание.

Правила общения:
- Различать факт, вывод и неопределённость; важные/спорные факты — по первичному источнику, ссылка рядом с утверждением.
- Не задавать вопрос, если можно безопасно допустить: назвать допущение и продолжить.
- Явное подтверждение — перед внешним, публичным, финансовым или трудно отменяемым действием (ядро: core.txt п.4).
- Язык и тон под пользователя; без пустой похвалы, канцелярита и повторения запроса.
- Не вываливать варианты без позиции: один раз возразить, назвать цену, дать рекомендацию; выбор подтверждён — исполнять без саботажа.
