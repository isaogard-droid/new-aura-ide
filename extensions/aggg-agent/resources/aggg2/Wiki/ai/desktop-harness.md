# desktop-harness — «руки для macOS»: Grok Build управляет GUI настоящего Mac

Оригинальный пост:

👍 desktop-harness - Руки для macOS

Инструмент, который позволяет Grok Build управлять настоящим Mac: открывать приложения, нажимать на элементы интерфейса, вводить текст и двигать мышь так же, как это делал бы человек.

Оптимизировано так, чтобы управление компьютером было максимально быстрым и эффективным.

Большинство агентов для управления компьютером сильно зависят от такой схемы:

Скриншот → анализ изображения → определение места для клика → новый скриншот → повтор

Это работает, но, по моему опыту, для повседневных задач такой подход не очень практичен. Он медленный, и даже выполнение простых действий может занимать очень много времени.

Раньше Grok Build мог выполнять shell команды на вашем Mac.

Теперь, благодаря этой системе, он способен взаимодействовать и с графическим интерфейсом macOS.

Shell → Accessibility → мышь и клавиатура → скриншоты при необходимости

https://github.com/xfreeze2/desktop-harness

## Контекст

- Пост готовый, ссылка не проверялась (по указанию автора).
- Проблема, которую решает: классическая схема GUI-агентов «скриншот → анализ → клик → скриншот» медленная для повседневных задач.
- Подход: вместо скриншотов как основного канала — цепочка Shell → Accessibility API → мышь/клавиатура → скриншоты только при необходимости. Accessibility-дерево даёт агенту структуру интерфейса (быстрее и точнее, чем пиксели).
- Целевой агент: Grok Build (управление macOS).

## Вывод

desktop-harness — показательный пример тренда в computer-use агентах: уходить от «слепого» скриншот-цикла к структурному доступу (Accessibility API), используя скриншоты только как fallback. Тот же паттерн (структура вместо пикселей) встречается в browser-use агентах (DOM вместо скриншотов) — на десктопе его роль играет Accessibility-дерево.
