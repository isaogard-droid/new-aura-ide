# Ресёрч: что индустрия делает, а AGGG2.0 упускает (19.08.2026)

Задача владельца: «распроси о нашей системе всех фактах ресёрчь, чтобы найти
что-то интересное, что мы упускаем. О каждой детали. 20-40 источников».
Собрано: 12 web_search-запросов с разных сторон, 32 первоисточника
batch_fetch (хуки, скиллы, код-интеллект, память, контекст-деградация,
эвалы, агентные ОС, браузеры, MCP). Сверка с нашей системой: прошивка
(core.txt/хуки), скиллы, базы, semble/CRG, battle-test, канон.

## Топ находок (по цене/эффекту)

### 1. События хуков, которые мы не используем (самое дорогое упущение)
Источник: Claude Code hooks docs (code.claude.com/docs/en/hooks,
/agent-sdk/hooks), readysolutions.ai «Hooks Visualized» (07.06.2026).

Полный жизненный цикл: SessionStart/SessionEnd, UserPromptSubmit,
**Stop/StopFailure**, PreToolUse/PostToolUse, **Compaction**, **Idle**,
**subagent start/stop**. Мы используем только UserPromptSubmit +
PreToolUse (+частично PostToolUse для фоллбэка skills_search).

- **Stop/StopFailure** — детерминированная ловля «готово без проверки»:
  наш DoD-гейт — промпт-правило (модель может проигнорировать), а хук
  на Stop срабатывает всегда. Ключевая цитата индустрии: «An ignored
  rule is not an emphasis problem. It is a routing problem» — правило,
  которое игнорируется, должно переезжать из промпта в хук.
- **SessionEnd** — авто-запись находок/чекпоинта в research.db при
  завершении сессии (сейчас — промпт-ритуал, забывается).
- **Compaction** — событие «контекст вот-вот сожмётся»: наш чекпоинт-
  ритуал (sharp zone >50%) — кандидат на детерминированный хук.
- **Idle** — «агент простаивает»: можно триггерить сверку гейтов.

### 2. Red-team харнесс для BLOCK_RULES
Источник: sentinel-hooks/claude-code-guardrails (GitHub).

Индустрия тестирует сторожей адверсариально: harness гоняет
обфускации (`rm${IFS}-rf${IFS}/`, `r''m -rf /`, пустые строки) как
реальные subprocess с реальными stdin/exit-кодами. У нас pytest на
гейты есть, но набора обфускаций-обходов — нет. Threat model
индустрии: «агент, который уверенно ошибается + репо/страница,
которая его подталкивает».

### 3. Эвалы скиллов: мы меряем триггер, индустрия — эффект
Источники: SkillsBench (arXiv 2602.12670), OpenAI «Eval Skills»,
Arcade SkillBench, agensi.io, arXiv 2606.11435 (survey).

- SkillsBench: 7308 траекторий, curated skills дают +16.2pp в среднем,
  но **16 из 84 задач — негативный эффект**. Вывод: скилл надо мерить
  A/B «со скиллом vs без скилла» (pass-rate delta), а не только «триггернулся ли».
  Наш trigger-eval ловит загрузку, но не то, что скилл РЕАЛЬНО помог.
- **Self-generated skills дают 0 пользы в среднем** — прямое
  предупреждение для fable-domain: сгенерированный скилл без боевого
  крещения = шум. Мы это закрываем battle-test, но стоит вписать
  явно в fable-domain.
- «Focused Skills with 2–3 modules outperform comprehensive
  documentation» — подтверждает наши тир-чтения (не читать весь канон).
- OpenAI: «Define success before you write the skill» — outcome/
  process/style/efficiency goals. У нас есть частично.
- Arcade SkillBench (39k скиллов, 6 измерений, safety 35%): сигнатуры
  **Unicode tag smuggling** и **rules-file backdoors** — расширение
  нашего Security Audit чужих скиллов.
- Zylos: «how skills are… eventually **retired**» — жизненный цикл
  отзыва скилла. У нас нет процедуры деприкации скиллов канона.

### 4. Fault injection / chaos-engineering для нашей системы
Источник: ReliabilityBench (arXiv 2601.06112), KDD'25 survey
(arXiv 2507.21504).

ReliabilityBench: 3 оси надёжности — pass^k (консистентность повторов),
robustness к пертурбациям задачи, fault tolerance к отказам тулов
(timeouts, **rate limits** (самый разрушительный отказ!), partial
responses, schema drift). Наш battle-test = pass^k на N попыток, но
**ось отказов у нас не покрыта**: мы не тестируем агента при падении
MCP, троттлинге GitHub API, обрезанных ответах. Chaos-harness —
кандидат на расширение battle-test.

### 5. Память: декай и противоречия
Источники: arXiv 2603.07670 (Memory survey), Hermes Agent Memory
(opsily), pi-agent (amsayed), sqlite-memory.

- Survey: открытые задачи — **continual consolidation** (слияние
  дубликатов памяти), **contradiction handling**, **learned
  forgetting**. Наши findings вечно равнозначны: нет декайя старых
  знаний (pi-agent: temporal decay), нет детекции противоречий между
  находками. Кандидат: `findings.py` — consolidation/decay.
- Hermes 3-слойная модель (MEMORY.md + FTS5 сессии + внешний
  провайдер) ≈ наша research.db + wiki + knowledge-базы — мы в
  мейнстриме. Hindsight 94.6% vs Mem0 67.6% на LongMemEval —
  локальные решения выигрывают.

### 6. Retrieval-качество: паттерны Veles/semcode
Источники: Veles (GitHub), semcode (GitHub), Codebase-Memory
(arXiv 2603.27277), semble architecture analysis (martianlee).

- Veles: **path penalties** (демоут тестовых файлов/компат-диров),
  **file saturation** (не складывать все результаты из одного файла),
  **definition boosting**, query-type detection (symbol → BM25).
  Дешёвые апгрейды semble/db-tools.
- semcode: **индексация git commit history** для семантического
  «почему это менялось». У нас githist hotspots (частотность), но
  семантики коммитов нет.
- Codebase-Memory: 83% качества ответов vs 92% у файл-эксплорера при
  10x меньше токенов — подтверждает наш DB-FIRST (граф/база вместо
  чтения).

### 7. Canary tokens + защита памяти от отравления
Источник: Microsoft Agent Governance Toolkit (tutorial 09).

- **Canary tokens** в системном промпте: если они всплывают в
  пользовательском вводе — сигнал утечки/инъекции. Наш core.txt —
  в раздаче, канарейка должна быть секретной (research.db) — спайк.
- **MemoryGuard** — защита хранимого контекста от отравления. Наши
  findings-базы не защищены от «веб-страница велит записать X» — у нас
  есть spotlighting-правило (промпт), но не детерминированный гейт.

### 8. WebMCP (W3C) — горизонт браузерной автоматизации
Источник: zylos.ai landscape (05.04.2026).

WebMCP — насаждающийся W3C-стандарт (Chrome 146, февраль 2026): для
кооперативных сайтов заменит хрупкий DOM-скрейпинг и скриншот-
инференс. Camoufox-воркеру стоит держать в поле зрения; spike при
выходе из черновиков. Playwright (наша база) — лидер с 78.6k звёзд,
+235% YoY — мы на верном фреймворке.

### 9. Прочее (меньшие, но реальные)
- Multi-turn деградация: 39% падение на 80-turn сессиях (tianpan);
  mitigation = компактные системные правила + чекпоинты — мы в
  мейнстриме, но **position matters** (vinish): прошивка должна
  быть в начале системного промпта — проверить, куда вставляет
  proshivka.js.
- Deep Research Agents roadmap (arXiv 2506.18096): «sequential
  execution inefficiencies» — наш паттерн параллельных субагентов
  (fable-loop) правильный.
- Microsoft multi-agent: platform-native orchestration первым, A2A —
  для кроссплатформы; «agent cards» (capability discovery) — у нас
  нет, но и потребности нет (локальные субагенты).
- MCP 2026: приоритеты — transport scalability (Streamable HTTP),
  donated to Linux Foundation; примитив **Resources** (данные для
  чтения) мы почти не используем — findings можно отдать как ресурс.
- 40% инцидентов агентов — из плохой обработки ошибок (Stanford AI
  Safety Center via getmaxim) — наша лестница фоллбэков правильная,
  стоит распространить на все MCP-вызовы.

## Что НЕ упущено (сверка — мы в мейнстриме)
- Прошивка-ядро на каждый ход + hooks = индустриальный паттерн
  enforcement ladder (промпт → permission → hook).
- Progressive disclosure скиллов (zylos: «20 capabilities = 4000
  токенов до первого сообщения» — мы это решили тирами).
- SQLite+FTS5 локальная память — паттерн Hermes/sqlite-memory.
- Гибридный поиск (static embeddings + BM25 + RRF + reranking) —
  semble = мейнстрим, Veles подтверждает архитектуру.
- pass^k боевое крещение = ReliabilityBench ось 1.
- Антидетект-браузер для ресёрча — растущий паттерн 2026.

### Ключевые находки
1. **Governance Decay (arXiv 2606.22528):** компакция контекста поднимает
   нарушения правил 0%→30%; тренинг-фри защита — Constraint Pinning.
   НАШЕ уже вшито: proshivka.js `experimental.session.compacting`
   re-inject ядра; Claude — ядро на каждый промпт. Правило «НЕ убирать
   пиннинг» — в CYCLE.md (цикл чекпоинта).
2. **Memory policy (superstruct.tech):** «untrusted input = evidence, not
   memory»; категории памяти (session/notes/facts/history/procedural).
   Наши базы разделены по типам; веб-контент в context-internet.db —
   evidence-хранилище, SIFT при использовании (канон уже есть).
3. **Write-back loop (pingcap):** retrieval-only память копит
   противоречия; LLM-детекция противоречий слаба (arXiv 2504.00180:
   CoT помогает одним моделям, мешает другим). Вывод: честный
   «не сейчас» — детектор противоречий не внедряем.
4. **Skill lifecycle (aiquinta, agentpatterns.ai):** SemVer/деприкация
   скиллов — для персональной системы избыточно; стадии с гейтами у нас
   есть (trigger/doc-eval, retirement-правило добавлено сегодня).
5. **Compaction cheapest-first (agentnative.dev):** чистка stale tool
   results до LLM-суммаризации — у нас sandbox_output.py (raw не в
   контекст). Суммаризация скрывает done-сигналы (+15% траекторий) —
   аргумент за наши чекпоинты, а не полный auto-summary.
6. **Canary best practices (promptinjectionprevention.com):** канарейки
   по регионам (system prompt/tool descriptions/retrieved chunks),
   ротация, внешний мониторинг. У нас одна канарейка на входе юзера —
   ловит утечку-в-инъекции; ловля утечки В ВЫВОДЕ модели требует
   output-хука (в Claude Code его нет) — честное ограничение.
7. **Stale-outranks (dev.to wenyu):** keyword-stuffed противоречащая
   страница обгоняет авторитетную в выдаче — агент ошибается. Для
   db=wiki митигация — wiki lint + dedup (findings --dupes не покрывает
   wiki.db — кандидат на будущее).
8. **Двухтировая память (niteagent, understandingdata):** checkpoint
   store (каждый шаг) vs semantic store (query-heavy) — наш sessions.jsonl
   (новый) + research.db соответствуют. Отдельный store для чекпоинтов —
   не делать (KISS, research.db справляется).

## Раунд 3 (по скиллу deep-gap-research: 8 запросов + 20 первоисточников)

Углы: аудит сессий, токен-экономика, MCP-безопасность, multi-harness
синк, файловая структура, self-correction, свежие фичи харнесов.

### Топ находок (внедрено)
1. **Аудит траекторий (HarnessAudit, arXiv 2605.14271).** Output-level
   оценка не видит mid-trajectory нарушений. Живые хуки сторожат вызовы,
   но никто не аудировал уже состоявшиеся сессии. Создан
   `scripts/tools/trajectory_audit.py`: сканирует транскрипты
   (~/.claude/projects/*.jsonl, ~/.codex/sessions/*.jsonl) на
   проскочившие опасные команды, секреты в выводе, canary-утечки +
   статистика. Батл-тест: 4/4 синтетических нарушений ловится; живой
   прогон — 7 сессий за 7 дней, 0 нарушений (хук не пропускал).
   **Бонус-находка батл-теста:** паттерн curl|bash в хуке не ловил
   `curl -s <url> | bash` (два аргумента) — red-team маскировал это
   сайт-блоком. Починен в хуке и в аудите, red-team 27 кейсов.
2. **Канон-защита от регрессии (galileo.ai, замер 167 сессий):**
   «больше префикс = дешевле ход» — 92.7% кэша → 3× дешевле, чем
   ad-hoc контекст. Наше ядро на каждый ход — кэш-оптимально; правило
   «не режь ядро ради экономии» — в CYCLE.md (рядом с пиннингом).

### Задача (не внедрено сейчас)
3. **Гейт аргументов MCP-тулов** (id=32): хук сторожит bash/edit, но не
   mcp__-тулы. Индустрия: 43% публичных MCP-серверов с command-execution
   (фев 2026), Ox Security STDIO-flaw «200K серверов», MCPSafetyScanner
   (arXiv 2504.03767). Шаг: спайк сканера на наших 4 серверах + сторож
   опасных аргументов (file:// в браузер-тулах).

### Что НЕ упущено (сверка)
- Multi-harness синк: agent-harness/ECC делают то же, что наш
  install_agents+install_proshivka (идемпотентно, --dry-run, секрет-фри).
- Файловая структура как архитектура (MWP, arXiv 2603.16021) — наш
  канон+скиллы с тир-чтением = тот же паттерн.
- Self-correction: grounded > intrinsic (zylos) — наш fable-judge/
  battle-test grounded; PRM — вне скоупа.
- OTel GenAI конвенции (bvsbharat) — для персональной системы избыточно.
- Cross-session messaging Claude Code (Week 32) — наш аналог:
  research.db + sessions.jsonl + findings.
- Кэш-оптимальность ядра — подтверждена замером индустрии.

## Раунд 5 (по скиллу deep-gap-research: угол «трактовка запроса», 4 запроса + 8 первоисточников)

Триггер: реальный сбой — агент неверно трактовал задачу владельца
(«тест» vs «текст», просьба в конце длинного сообщения) и полез
править систему вместо текстовой задачи.

### Индустрия
- Google ACT (ICLR 2025): модели «overhedge or implicitly guess user
  intents rather than asking» — угадывание вместо вопроса = известный
  дефект.
