Соглашение (пункт #3 обшивки баз): каждый ГЛУБОКИЙ ресёрч (выбор подхода,
проектирование, «как делают в индустрии») оставляет отчёт в этой папке.
В research.db уходит только вывод (`findings.py add`), а сырьё — план,
источники, отсеянное — здесь. Так ресёрч можно переиспользовать и
аудитировать, а не терять.

1. Файл: `docs/research/<ГГГГ-ММ-ДД>-<тема-коротко>.md` (латиницей/цифрами,
   дефисы вместо пробелов).
2. Структура — по шаблону `TEMPLATE.md`: вопрос → план/под-вопросы →
   источники → отсеянное → выводы.
3. В выводе — ссылка на findings id (`findings.py add ... --source
   docs/research/<файл>.md`), а в отчёте — на findings id, если он уже есть.
4. Мелкий ресёрч (справка, 2-3 источника) — отчёт не обязателен, хватает
   findings.

## Метрики и связи — рядом

- Что мы реально ищем в базах: `python3 db-tools/search.py --stats`
  (search_log: топ запросов, пустые результаты).
- Связи находок (что с чем связано): `findings.py link add/list/rm`,
  `findings.py related <id>`, `findings.py show <id>`.
- Авто-кандидаты из истории сессий: `python3 db-tools/extract_findings.py`.
