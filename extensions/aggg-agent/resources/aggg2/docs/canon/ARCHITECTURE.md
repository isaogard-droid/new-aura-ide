# ARCHITECTURE — слои, лимиты каталогов, связи

Правила организации воркспейса: слои, деление каталогов, связи. Парный док FILE-SIZE.md — про размер ФАЙЛОВ; этот — про КАТАЛОГИ и зависимости. Основа: Clean Architecture (Dependency Rule), Nx/monorepo layouts, Python project structure.

## 1. Принципы
1. **Слой = граница доверия**: код слоя меняется по одной причине и одной скорости. Смешивать скорости = правка быстрого ломает медленное.
2. **Зависимости — вниз, не вверх и не вбок.** Между слоями — только по мостам (п.4). Циклы запрещены.
3. **Деление по доменам, не по типам файлов** (install/, doctor/, eval/, tools/).
4. **README-карта на каждый слой** — без README-индекса каталог не готов к приёму новых файлов (SSOT).
5. **Агенты — изолированные юниты**: специфика только в `agent/<имя>/`, в общий контекст не грузится.

## 2. Слои
| Слой | Что живёт | Скорость | Импортировать можно из |
|---|---|---|---|
| `harness/` | ядро прошивки (core.txt, плагины, хуки) | медленно (правила) | — (не код) |
| `projects/` | приложения-проекты (sherpa-voice, ...) | по проекту | db-tools, scripts, внешние |
| `mcp/` | MCP-серверы воркспейса | средне | db-tools, scripts (`_compat`, `jsonc_edit`) |
| `db-tools/` | движок баз | средне | scripts (`_compat`), между собой |
| `scripts/` | управление (install/doctor/eval/tools + кирпичи) | быстро | между собой, db-tools (редко) |
| `agent/<имя>/` | изолированный агент | автономно | только внутри себя |
| `docs/`, `skills/`, `Wiki/` | знания | по контенту | — |

## 3. Лимиты каталогов
- **≤ 15 файлов-братьев** (не считая README.md, tests/, __pycache__): больше — делить по доменам (п.5). Проверено: 30 файлов в scripts/ читались плохо → деление вернуло навигацию.
- **Глубина вложенности ≤ 3** от корня слоя.
- **Корень воркспейса** — только главные канон-доки и служебное (README, VERSION, make_archive); остальное — docs/.
- Исключения осознанные: `skills/` (49 каталогов — стандарт Agent Skills), вендор (fable-method/eval), кэши (.gitignore).

## 4. Связи (мосты)
Разрешённые импорты — ТОЛЬКО эти; новые мосты — с обоснованием в CHANGELOG:
```
projects → db-tools, scripts, mcp-тулы (как клиенты)
mcp      → db-tools (search, log, repomap, search_all)
mcp      → scripts (_compat, jsonc_edit)
db-tools → scripts (_compat)
scripts  → scripts (внутри своего слоя)
agent/*  → (ничего наружу; субагент читает $AGGG2_ROOT доки — чтение, не импорт)
```
Нарушение ловит doctor-чек `layer-boundaries` (ошибка), разбор — в базе и CRG.

## 5. Процедура деления каталога (как резка FILE-SIZE)
1. **Данные, не ощущения**: файлы-братья; карта импортов из базы (`search.py --imports` / sqlite imports).
2. **Группировка по доменам** — кластеры по причине изменения.
3. **Перенос механический**: файлы verbatim, sys.path-вставка на родителя в каждом, корень `parent.parent` → `parent.parent.parent` (проверить ВСЕ).
4. **Ссылки через базу**: FTS-поиск имён (`files_fts MATCH`) → замена `путь/имя` во всех упоминаниях (доки, CI, тесты, core.txt).
5. **Проверки**: ruff → ВСЕ тесты → doctor (0 ошибок) → база пересобрана → CHANGELOG-запись.
6. README-карту слоя обновить ПЕРВЫМ делом.
Грабли (15.08): замена подстрок ловит вложенные имена («ASK-NODUMB.md» ⊃ «NODUMB.md»); `'.git' in root` матчит `.github`; после переноса скрипт-генератор проверять doctor'ом.

## 6. Enforcement
- `doctor.py` → `layer-boundaries` (ошибка) и `context-budget` (warning).
- `check_file_sizes.py` — размеры файлов; новый каталог без README — doctor-предупреждение.
- CI: тесты + doctor + file-sizes на 3 ОС.
