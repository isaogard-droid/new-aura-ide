# ask-nodumb — продуктовый консультант

Скилл для задач, где **решение приходит раньше понимания**: новая фича, экран, флоу, редизайн, концепт, UX. Связывает в единую картину человека, его обстоятельства, задачу, ограничения и характер продукта. Полный текст и справки: `skills/ask-nodumb/SKILL.md`.

## Зачем нужен (какую боль закрывает)
**Экран — следствие, а не цель.** Вопрос, разворачивающий решение, дороже мгновенного ответа. Без скилла агент рисует то, что просили, вместо того, что решает проблему: кнопка/паттерн/технология в запросе — уже ОТВЕТ пользователя.
Три слоя задачи, лечить надо тот, где причина:
| Слой | Вопрос | Что это |
|---|---|---|
| **Образ** | зачем и каково это | характер продукта, система координат |
| **Модель** | как устроено | сущности, правила, состояния |
| **Технология** | чем выражено | реализация, компоненты |

## Когда использовать (триггеры)
| Использовать | НЕ использовать |
|---|---|
| «придумай/переделай фичу, экран, флоу» | исполнение согласованного решения |
| «как спроектировать», «с чего начать» | точечная визуальная правка (цвет, шрифт) |
| «какой вопрос задать» | техническая реализация без продуктовой развилки |
| запрос сразу предлагает решение | — |
| варианты кажутся равнозначными | — |

## Как работает (ход консультации)
1. **Назвать, чего не хватает**: контекста, образа, модели или реализуемости — прямо, не списком общих вопросов.
2. **Занять позицию**: что главное, какое предположение самое дорогое и почему. Вопросы — только те, что могут ИЗМЕНИТЬ решение. Не допрашивать, не идти по списку ради галочек.
3. **Фокус на напряжении**, а не на принесённом решении.
4. **Разводить факт, интерпретацию и выбор**; эстетика не выдаётся за правило.
5. **Дать рекомендацию**, когда данных достаточно: предпочтительный ход, его цена и что могло бы его опровергнуть. Не оставлять с веером равных вариантов.
Уровни работы (философский / архитектурный / визуально-системный) — не этапы: включается тот, где причина решения; справки — в `references/` скилла (один уровень, одна неопределённость).

## Итог для пользователя
Обычно остаются четыре вещи: что видно сейчас, что пока предположение, какую развилку выбрать и чем проверить выбор. Не закрывать разговор «готовым решением» без указания, для кого и в каком контексте оно работает.
