# fable-domain — новые доменные скиллы

Генератор доверенного бандла для домена: workflow с flowchart, доменный адаптер, trap-фикстура, smoke-eval. Полный текст: `skills/fable-domain/SKILL.md`.

## Зачем нужен (какую боль закрывает)
fable-method поставляется с адаптерами (coding — дефолт; marketing, research, data, business/ops, finance, legal/compliance, design, devops). Адаптер меняет только существительные, не цикл. fable-domain создаёт НОВЫЙ адаптер — по записи реального процесса, не по догадке.

## Что производит (бандл; все четыре, или не готово)
1. **Workflow с flowchart** — пошаговый подход для домена (user-facing).
2. **Адаптер** по шаблону `references/domains/TEMPLATE.md` — каждая норма/политика/цифра с добытым источником.
3. **Trap-фикстура** — маленький eval: заманчивый ход = центральное мошенничество домена, правильный = дисциплина workflow, нарушение объективно детектируется.
4. **Smoke-eval** — 1-2 прогона «без бандла vs с бандлом», судится диффом; помечается как smoke; оставшийся долг объявляется.

## Этапы
**Stage 1 — Обсуждение.** Разговор: реальный кейс и кто им пользуется; что такое «хорошо» в домене; какие источники доверяет пользователь; что скилл никогда не должен делать; что должен производить. Стоп, когда можешь повторить пользователю его доказательства/авторитеты/провалы и он согласен.
- **Red-lines (жёсткий отказ)**: домен требует лицензии или неверный ответ причиняет физический/юридический/финансовый вред (медицина, юр-советы, конкретные финансовые сделки, психология, safety-critical) — НЕ генерировать чеклист-костюм компетентности; маршрут — к квалифицированному человеку.
- **Scope stop (ранний выход)**: сектор не наполняет шаблон НОВЫМИ существительными — остановиться: метод уже покрывает это. Дебаг, рефакторинг, тесты — дефолтный домен.
**Stage 2 — Ресёрч.** Ограниченный веб-ресёрч, добытый СЕЙЧАС: что практики считают доказательством, реальные авторитеты, актуальные регуляции, документированные провалы (сырьё для таблицы фродов). Каждое утверждение с нормой/порогом — со ссылкой и датой доступа. Нет веба — нет доверенного бандла.
**Stage 3 — Генерация.** Прочитать ВСЕ существующие адаптеры (не выборку); очертить сектор; workflow+flowchart; адаптер строго по TEMPLATE; вшить каждую routing-точку (список адаптеров в методе, README, fable-judge); trap-фикстура (минуты на прогон).
**Stage 4 — Проверка и отчёт.** Механические проверки репо; smoke-eval (одно зерно = smoke, не бенчмарк; trap без разницы = бандл непроверен); **fable-judge pass по собственным утверждениям бандла** (каждый источник реально добыт, trap проверен в трёх состояниях, routing вшит, цифры smoke совпадают) — не прошедший судью бандл не готов; отчёт результатом первым с честной строкой долга.

## Важные границы
- Существующий сектор — обновление, не дубликат.
- Публикация/коммит бандла — только с разрешения пользователя (гейт AUTH).
- Скилл структурирует доменную работу, но не даёт доменного авторитета: red-lines, smoke-лейбл и Sources — чтобы эксперт проверил бандл за минуты, а вредные домены не получили чеклист вовсе.
- Качество зависит от модели: maker — мид-тир или лучше (или осознанно вручную); отказные гейты держатся и на слабой модели.
