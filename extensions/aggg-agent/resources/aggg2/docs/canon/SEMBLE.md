# Semble — семантический поиск по коду (MCP)

Смысловой поиск по коду и докам: «найди код, который…» — без грепа. Эмбеддинги (potion-code-16M) + BM25 + code-aware reranking. Возвращает только релевантные чанки с путём и строкой — 98% меньше токенов, чем grep + read.

## Что это
- **Сервер**: `mcp/semble_mcp.py` (обёртка над `semble` 0.5.5, вендор в `~/.venvs/aggg2`).
- **Инструменты**: `search` (смысл → файл+строка), `find_related` (похожий код рядом с локацией: реализации интерфейса, вызовы, тесты).
- **Индекс**: один раз на репо, кэш (`~/.cache/semble`, env `SEMBLE_CACHE_LOCATION`); повторные запросы — мгновенно.
- **Покрытие**: CODE + DOCS + CONFIG (`.py .js .sh .md .yaml .yml .toml .ini` и др.). **Не индексируются**: `.json`, `.jsonc` (библиотечное ограничение).
- **`.sembleignore`** — негативы поверх `.gitignore` (негативы перебивают): вложенные репо (`skills/fable-method/`, `projects/sherpa-voice/`) поиску ВИДНЫ; `!harness/core.txt` обходит фильтр расширений. Батл покрытия 19.08: 686 → 875 файлов (82% → 94%).

## Для чего
| Вопрос | Инструмент |
|---|---|
| «Где код, который обрабатывает ошибки?» (по смыслу) | **semble.search** |
| «Где определён символ X / кто его вызывает?» (структура) | db-tools (search/--symbol/--calls) |
| «Все ссылки на символ, типы, скоуп, rename» | agent-lsp |
Порядок: (ядро: core.txt п.2). Не греп: Semble дешевле и точнее.

## Использование
```
tools.semble.search({ query: "как обрабатываются ошибки", repo: "/path/to/root", top_k: 5, max_snippet_lines: 10 })
tools.semble.find_related({ file_path: "...", line: 42, repo: "/path/to/root" })
```
- `query` — короткий смысловой запрос или имя функции/класса. **Не** текст ошибки.
- `repo` — локальный путь или https:// URL удалённого репо.
- `max_snippet_lines` — 10 (сигнатура+тело) / 0 (путь+строка) / None (полный чанк). Не подтвердил локацию — повтори с None.
- `content` — сузить: code/docs/config/all (по умолчанию — конфиг сервера).

## Грабли
1. **`.json`/`.jsonc` вне индекса** (eval-кворies/results скиллов, конфиги плагинов) — не патчить: eval-артефакты засоряют выдачу, конфиги читаются напрямую (db-tools или read). `.txt` ядра — в индексе через `.sembleignore`.
2. **Запрос — термины дока, не бытовой пересказ.** Батл 19.08, 15 перефразов × 4 пути (топ-5): semble raw — 2/15; **semble + термины — 15/15**; db-tools FTS — 6/15; multi-query RRF со стеммами — 14/15 (дороже — отвергнуто). Схема: не знаешь терминов — возьми из db-tools (ловит 40% перефразов сам), потом semble. Длинные русские фразы размывают вектор: «судья ревьюеров вердикт» находит multimodel_judge.py, «мультимодельное судейство кода несколькими моделями» — нет. Формула: термины + короче + можно по-английски. Русское покрытие решают термины + BM25, не мультиязычная модель (A/B: potion-code-16M-v2 13/13 top5; findings id=959, 960).
3. **Первый запрос по репо — самый дорогой** (индексация). Тёплый кэш — истина.
4. **Ранкер не иерархический**: «где лежит X» по имени — db-tools; Semble — для смысла.

## Переподключение MCP без рестарта opencode
Если MCP-процесс semble умер или скрипт изменён (opencode не рестартует подпроцесс):
1. `kill <pid>` (pgrep -af semble_mcp).
2. Тоггл в `~/.config/opencode/opencode.jsonc`: `"semble"."enabled": false` → сохранить → через 2 с → `true` → сохранить. config.updated переподключает сервер; индекс пересоберётся автоматически.
