# fable-method — цикл решений

Пошаговый цикл решения задач: классифицируй → определи «готово» → собери доказательства → реши → действуй → проверь наблюдением → отчитайся результатом первым. Полный текст и справки: `skills/fable-method/SKILL.md` (+ `references/`: failure-modes, examples, flowcharts, domains).

## Зачем нужен (какую боль закрывает)
**Мид-тир модель, следующая этому циклу, бьёт более сильную модель, которая импровизирует**: качество живёт в структуре, доказательствах и честности, а не в модели.

## Ключевые идеи
- **Triviality gate (первым)**: задача тривиальна только если ВСЁ сразу — один файл, <10 строк, без нового поведения, и уже знаешь что менять. Тогда — быстрая правка и отчёт в 1-2 предложения. Всё остальное — полный цикл.
- **Fit gate (вторым)**: где лежит ответ? В источниках (открываются) → цикл; в неизвестной технике → сначала ресёрч; только в твоей голове → честно сказать, не наряжать догадку в «строгий процесс».
- **Шаги структурируют работу, не отчёт**: в ответе пользователю нет номеров шагов; из артефактов — только строки INTENT / AUTH / PENDING / TWINS, когда они положены.
- **Доменные адаптеры**: меняют существительные, не цикл (что считать доказательством, кто авторитет, какие мошенничества).
- **Гейты**: authorization (необратимое — только с точными словами пользователя, строка `AUTH:`), intent (до правки поведения — `INTENT:`), twin-check (баг найден — искать близнецов, `TWINS:`), artifact-gate (перед отчётом — все owed-строки на месте).

## Режимы
```
/fable-method <task>        полный цикл
/fable-method plan <task>   шаги 0-3: классификация, done, доказательства, план — и стоп
/fable-method audit         оценка сделанной работы против цикла (followed/skipped/faked)
/fable-method report        переписать ответ по чеклисту шага 6
```

## Когда использовать
- любая многошаговая задача, которую не покрывает свой скилл; «сделай по fable-методу», «подойди как Fable»; когда сомневаешься — цикл по умолчанию для нетривиального.
