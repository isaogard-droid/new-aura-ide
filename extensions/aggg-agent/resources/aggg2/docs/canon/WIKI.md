# WIKI.md — библиотека знаний Wiki/: универсальный протокол

Wiki/ — markdown-библиотека знаний (паттерн **LLM Wiki Karpathy**: знание компилируется
один раз, не пере-выводится при каждом запросе, как в RAG). Ведёт агент. Инструменты:
скилл `wiki-karpathy`, база `db/wiki.db`, `index.md`/`log.md`.

## Что такое Wiki (и чем НЕ является)

| | Wiki/ | research.db | skills/ | канон-доки |
|---|---|---|---|---|
| Что | продукт знания: посты, разборы | журнал: что выбрали/отвергли | процедуры по триггеру | правила воркспейса |
| Ищут | `db: wiki` (FTS), теги, index.md | `findings.py search` | auto-триггер | читают целиком (тиры) |

Куда класть: пост извне/узкая процедура → **Wiki/**; вывод ресёрча → **research.db**;
регулярная процедура → **skills/**; универсальная грабля → канон-док.

## Что МОЖНО класть в Wiki/

1. **Посты извне** (главный сценарий): пост/ссылка от юзера → MD с frontmatter
   и «Контекстом» (что это, как работает, вывод).
2. **Разборы инструментов**: что даёт, грабли, вердикт.
3. **Неоправданные скиллы (НАШИ)** — не прошедшие в `skills/` (узкие, редкие,
   экспериментальные; каждый скилл в пуле стоит токенов на каждый ход) — как
   **Howto-посты** (тег `skill-notes`, OKF `status`), в контекст не попадают;
   промоушен в ядро — вручную владельцем.
4. **Идеи, списки, справочники** (Idea/Reference); **инсайты** (Insight).

## Что НЕЛЬЗЯ класть

- **Секреты и креды** — (ядро: core.txt п.6); Wiki входит в раздачу и индексируется.
- **Внутренние механизмы защиты** и конфиденциальные детали (фильтр `make_archive.sh --list`).
- **Рабочие выводы решений** — это research.db.
- **Копии исходников/проектов** — для кода есть базы (`db-tools/build.py`).
- **Черновики сессий** — библиотека, не транскрипт.

## Структура

```
Wiki/
├── README.md          # правила библиотеки (схема) — источник истины, держать lean
├── index.md           # каталог — ГЕНЕРИРУЕТСЯ gen_index.py, руками не править
├── log.md             # append-only журнал (append >>, ротация при >500 строк)
├── log-archive/       # архив старых логов (log-<YYYY-MM>.md)
├── _templates/        # шаблоны (post.md)
├── ai/ coding/ tools/ # тематические папки (новая — при 3+ постах темы)
└── <slug>.md          # посты
```

Принципы: **файл = один концепт**; **путь = идентичность** (папка — категория, имя —
kebab-case); **теги — главный механизм поиска** (нижний регистр, дефис, английские).

## Как наполнять (ingest)

1. **Текст поста как есть** — не искажай; ссылку проверить через Camoufox. Папка + slug.
2. **Frontmatter** (обязательно: `type`, `title`, `description`, `date`, `tags`):
   ```yaml
   ---
   type: Post                    # Post | Insight | Reference | Idea | Howto
   title: Короткое название
   description: Одно предложение — о чём пост (для поиска и index.md)
   date: YYYY-MM-DD
   tags: [ai, 3d, tencent, agents]   # категория + 2-5 предметных
   source: https://...           # первоисточник (если есть)
   author: @канал                # автор/канал
   status: stable                # draft | stable | deprecated
   ---
   ```
   Опции OKF: `verified`, `stale_after`.
3. **index.md — СКРИПТОМ, не руками**: `python3 skills/wiki-karpathy/scripts/gen_index.py`
   (не читать целиком — сотни КБ контекста).
4. **log.md — append'ом, не читая файл**:
   `printf '%s\n' "- $(date '+%F %H:%M') — add — <файл> — что добавлено" >> Wiki/log.md`
5. **База**: `python3 db-tools/build.py -r Wiki -o db/wiki.db` (инкрементально).
6. **Lint**: `python3 skills/wiki-karpathy/scripts/lint_wiki.py` — 0 ошибок.

## Как пользоваться (query)

- Агенту: MCP db-tools → `search`, `db: wiki` (или `search.py -b db/wiki.db`). **Wiki
  ищется ВСЕГДА**: каждый поиск в любой базе заканчивается секцией «📚 Wiki (ищи
  всегда)» — топ-3 поста (реализация — `db-tools/wiki_section.py`). **Греп по Wiki/ —
  только человеку, агент — НИКОГДА** (файлы на внешнем диске — медленно; база —
  мгновенно и по всему посту).
- Человеку: `grep -ri "<тег>" Wiki/` или `index.md`.
- «Мы это уже разбирали» — `findings.py search`, потом Wiki; пустой результат —
  лестница (ядро: core.txt п.2).

## Проверка целостности (lint)

`python3 skills/wiki-karpathy/scripts/lint_wiki.py` — frontmatter на месте, поля заполнены,
теги в нижнем регистре без пробелов, имена kebab-case. После каждого добавления
(lint = eslint для знаний).

## Грабли и масштаб

- **index.md/log.md НЕ читать целиком** в контекст; поиск — через базу.
- **README.md держать lean** — он всегда в контексте.
- Потолок — не в файлах: flat + теги + FTS держат тысячи постов; сигнал к разделению
  на вторую wiki — домены без кросс-ссылок, не размер.
- Скилл-на-полке: Howto-пост, не поднятый в skills/ — пометить в description «не в
  пуле скиллов — почему».
- **Вынесенные скиллы** (редкие из `skills/`) — папка в `Wiki/skills-shelf/<имя>/`:
  `metadata.shelf: true` + `metadata.shelf_reason`; индексируется в `db/skills.db`
  (build.py --extra-root, префикс `skills-shelf/`) — загрузка только явная
  (SKILLS-LOCAL.md «Полка»).
- Новый пост влечёт 4 действия (index → log → база → lint) — пропуск любого = пост
  невидим для поиска.
