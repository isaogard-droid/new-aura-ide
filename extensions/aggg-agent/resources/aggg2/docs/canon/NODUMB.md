# nodumb — манифест здравого смысла

Скилл, который включается, когда **цена ошибки выше стоимости паузы**: перед дорогой развилкой, советом, планом, массовой правкой. Его работа — не дать уверенно двинуться в неверном направлении. Полный текст и справки: `skills/nodumb/SKILL.md` (в корне воркспейса).

## Зачем нужен (какую боль закрывает)
Самое дорогое — не ошибка в коде, а **уверенное движение в неверном направлении**: ошибку в коде видно по тестам, неверный курс — когда уже потрачены часы. Трижды свериться ДО:
1. **Правильная ли задача** — запрос почти всегда приходит в форме решения; решение проверяется только через задачу.
2. **Правильный ли масштаб** — точечная правка может прятать системную проблему, а «общий слой на будущее» — быть перерасходом.
3. **Появился ли новый факт** — повторная попытка на тех же данных воспроизводит предыдущий результат.

## Когда использовать (триггеры)
| Использовать | НЕ использовать |
|---|---|
| выбор подхода/инструмента/архитектуры | мелочи и простые факты |
| «как лучше сделать», «посоветуй», «стоит ли?» | продолжение согласованного |
| планирование рефакторинга/миграции/редизайна | — |
| повторная починка («не помогло») | — |
| запрос готовым решением | — |
Срабатывает даже если пользователь не называет это развилкой.

## Как работает (режимы)
Скилл не читается целиком каждый раз — включается режим по ситуации:
- **«Работа только начинается»** — сформулировать задачу от человека, назвать признак успеха, выделить самую дорогую развилку, назвать допущение и идти.
- **«Правка разрастается по проекту»** — пересчитать места и значения; общий источник — только при ОДНОЙ причине изменений; пилот на одном участке до массового переноса. Честный итог: «общий слой сейчас не нужен».
- **«Отладка застряла»** — перед второй правкой добыть НОВЫЙ факт; после двух неудачных правок считать метод исчерпанным; код менять только после нового наблюдения.

## Правила общения
- Различать факт, вывод и неопределённость.
- Не задавать вопрос, если можно безопасно допустить — назвать допущение.
- Явное подтверждение — перед внешним, публичным, финансовым, трудно отменяемым.
- Не вываливать варианты без позиции: один раз возразить, назвать цену, дать рекомендацию; решение пользователя исполнять без саботажа.
