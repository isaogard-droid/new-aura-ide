# Camoufox — веб-ресёрч по максимуму

MCP-сервер (`mcp/camoufox_research.py`) — веб-ресёрч через анти-детект
браузер (DuckDuckGo, чтение страниц, клики, ввод). **Веб-ресёрч — первое
действие** при любой задаче с выбором/неизвестностью (ядро — core.txt п.1,
CLAUDE.md «ВЕБ-РЕСЁРЧ»).

## Инструменты (9)

| Инструмент | Что делает | Когда |
|---|---|---|
| `ping` | проверка связи | перед длинной серией вызовов |
| `web_search(query, max_results=10, pages=1, include_snippets=False)` | поиск в DDG: номер/заголовок/URL; `pages>1` — пагинация; `include_snippets=True` — сниппеты под URL; КЭШ сутки | старт ресёрча |
| `research(queries, max_results_per_query=5, fetch_top=0, article_only=True)` | **норматив «10 источников» одним вызовом**: N формулировок → дедуп URL со сниппетами → `fetch_top>0` читает топ-N; кэш сутки | вместо серии web_search |
| `fetch_page(url, max_chars, article_only=False)` | текст без HTML-мусора; `article_only=True` — статья (Trafilatura) | читать статью/доку целиком |
| `batch_fetch(urls, max_chars, article_only=False)` | несколько URL в одном старте; батч ≥8 — параллельно (пул потоков, ~3x быстрее) | глубокий ресёрч: 30-50 URL одним вызовом |
| `browser_navigate` | текст + первые ссылки | ориентироваться |
| `browser_click` | клик по CSS-селектору или тексту ссылки/кнопки | интерактив: «дальше», табы, кнопки |
| `browser_type` | ввод текста в поле (CSS-селектор) | формы поиска, фильтры |
| `extract_links` | собрать ссылки (фильтр по подстроке) | ссылки на скачивание/исходники |

## Паттерны использования (проверено в работе)

### 0. Порядок ресёрча: быстрые пути → браузер
```text
1. база: search.py / findings.py / MCP db-tools      (секунды)
2. скиллы: db/skills.db → skills_search.py "<тема>" --top (~1с)
3. веб: web_search (3-5 запросов) → fetch_page первоисточники (10-30)
```

**Лестница веб-инструментов (жёсткий приоритет):** любая веб-потребность →
СНАЧАЛА Camoufox MCP (web_search/fetch_page/batch_fetch), если есть в
каталоге тулов; встроенные webfetch/websearch харнеса — ТОЛЬКО фоллбэк
(нет в каталоге ИЛИ пусто/ошибка после retry ≤1, circuit breaker);
всё пусто — честное «не нашёл». Camoufox умеет SPA/JS-страницы,
пагинацию, batch 20-40 первоисточников, обходит боты-защиту — встройка
харнеса не умеет.

**Две дорожки — обе нужны, не выбирай одну** (ресёрч 17.08, 24 источника:
arXiv 2506.18096, gpt-researcher, Hermes):
Дорожка 1 — ГОТОВОЕ РЕШЕНИЕ: skills_search.py (есть ли чужой скилл?)
Дорожка 2 — ПАТТЕРНЫ ИНДУСТРИИ: camoufox web_search (как делают другие)
Ответ есть в базе/скиллах — браузер не нужен (не жечь время и токены).

### 1. Стандартный ресёрч (как мы делаем всегда)
**Норматив: МИНИМУМ 10 источников на любую задачу** (10 — нижняя граница;
решения/выборы — 30-50, CAMOUFOX-DEEP.md).
```text
research(queries=["тема: как делают", "тема: паттерны индустрии",
                  "тема: проблемы/грабли"], max_results_per_query=5)
→ batch_fetch(лучшие 10+ URL)      # первоисточники, не пересказы
→ сверить: факт в одном — подтверждение в другом (2+ независимых)
→ findings.py add ...              # выводы — в research.db
```

### 2-5. Остальные паттерны (кратко)
- **Интерактив:** fetch_page(url) → browser_click(target_text="Продолжить"/
  "Вкладка") → browser_navigate — статьи с пагинацией, табы, формы.
- **Файлы/исходники:** extract_links(url, pattern=".zip"|"download"|".wav").
- **Формы:** browser_type(url, selector="input[name=q]", text="...") → fetch_page.
- **Документация — для ВСЕГО, актуальная** (память отстаёт от версий):
  web_search("docs <фреймворк/API> <версия> <тема>") → fetch_page
  (официальные доки/спека/исходник) → сверка с changelog при расхождении.

### 6. JS-страницы (SPA, React/Next/Vue) — умеем, с 17.08.2026
Сайты рендерят контент СКРИПТОМ ПОСЛЕ загрузки HTML (сервер отдаёт
оболочку, JS рисует текст). Воркер умеет это автоматически — отдельные
вызовы НЕ нужны:
- fetch/batch/navigate/click/type/extract_links ЖДУТ контент, а не время:
  `_wait_content` — поллинг текста + скролл до низа (lazy/infinite) +
  выход по стабильности (паттерн Browserbeam);
- после domcontentloaded — networkidle-затишье (до 5с, suppress) —
  JS-страницы делают API-запросы ПОСЛЕ DOM.

НЕ гадать «а вдруг там JS?» — открывать страницу как обычно. Контент
пустой (тяжёлый рендер >8с) — повторить вызов или browser_navigate.
Проверено живьём: skills.sh, react.dev, scrapingcourse.com, example.com.

## Исследовательский цикл — основа работы (как в индустрии)

```text
RESEARCH ──→ HYPOTHESIZE ──→ EXPERIMENT ──→ ANALYZE ──→ LEARN
    ▲                                                      │
    └────────────── research.db (база знаний) ◄────────────┘
```

- **RESEARCH** — собрать факты и артефакты (ширина → глубина).
- **HYPOTHESIZE** — проверяемое предположение с обоснованием («если X,
  то Y, потому что Z», не «попробуем»).
- **EXPERIMENT** — проверить реальным действием (запрос, клик, код,
  сверка источника), залогировать результат.
- **ANALYZE** — что подтвердилось, что опроверглось, почему.
- **LEARN** — выводы в research.db (findings.py add), правило в канон.

**Спираль, а не круг:** каждый виток со строго большим знанием — база
тащит знание вперёд. Виток 10 — с проверенными фактами, а не с нуля.
Поэтому findings.py — не бюрократия, а топливо цикла. **Баланс фаз:**
начало — тяжёлый RESEARCH; середина — HYPOTHESIZE+ANALYZE; затык (плато) —
ВЕРНУТЬСЯ в RESEARCH за новым знанием (другой подвод, смежная тема,
первоисточник), а не долбить те же гипотезы.

**SIFT — оценка источников (Michael Caulfield, WSU):** **S**top (не
доверять первому впечатлению) → **I**nvestigate (кто автор, откуда
материал) → **F**ind better coverage (независимое освещение) → **T**race
claims (вернуть к первоисточнику). Применять к каждому ключевому факту:
SIFT + триангуляция (2+ независимых источника) = оценка как у фактчекеров.

## Грабли (проверено на практике, не наступать)

Уникальные для камуфокса (общие правила — core.txt/CLAUDE.md):

- **Живой воркер: браузер держится между вызовами** (serve-режим).
  Первый вызов платит старт ~2-5с, дальше — тёплый браузер; для 30-50 URL
  используй `batch_fetch` (один старт на все).
- **Windows: headless может падать** (баг #614 daijro/camoufox,
  STATUS_BREAKPOINT) — воркер сам пробует fallback headless → headed +
  `windows_hide=True`. Другие Windows-баги — `mcp/README.md`,
  `scripts/install/update_camoufox.py`.
- **Пагинация DDG — только через POST-форму Next.** GET `&s=20` DDG
  игнорирует (проверено s=0/10/20/40). `web_search(pages=N)` сам делает
  правильный submit формы.
- **`fetch_page` обрезает длинные статьи** по `max_chars` (дефолт 6000) —
  для больших доков поднимать `max_chars=12000+`, иначе потеряете хвост.
- **Сайты падают/таймаутят** (GitHub иногда) — не застревать:
  переформулировать запрос, взять зеркало (pkg.go.dev вместо github),
  найти через web_search.
- **Поиск «ничего не нашёл»** — почти всегда формулировка: короче, без
  спецсимволов (дефис в `agent-lsp` ломает FTS — писать «agent lsp»),
  латиницей, на английском для технических тем.
- **TTS/синтетика распознаётся плохо** — для экспериментов искать реальные
  аудио (папки записей, test_wavs), не синтезировать.
- **Не ходить в браузер за тем, что уже есть в базе** — сначала
  search.py/findings.py, браузер — за новым знанием.
- **Кэш — проверяй перед повторным fetch.** fetch/batch кэшируют текст
  на сутки: повторный вызов отдаёт из кэша без браузера.
- **JS-страница может рендериться дольше 8с** — воркер ждёт до таймаута,
  отдаёт что успело; пусто — повторить (второй раз часто полный: кэш
  браузера тёплый) или browser_navigate.
- **НЕ ждать networkidle вручную** — воркер делает сам (suppress, лимит 5с);
  `wait_for_load_state("networkidle")` без таймаута может ждать вечно
  (playwright #19835, #41513: EventSource).
- **Страница каталога — страховка чтения скиллов** (стресс-тест 18.08):
  skills.sh рендерит SKILL.md с любой структурой и честно отдаёт
  «Did you mean» для удалённых. Уровень 4 чтения (raw → tree → fuzzy →
  страница каталога) — не пропускать при «не найден».

## После ресёрча — ОБЯЗАТЕЛЬНО

1. Выводы и решения — в `research.db`: `findings.py add "тема" --text
   "что нашли, что выбрали, что отвергли, ссылки" --tags "..."`; связи —
   `--related "id1,id2"` (`findings.py related <id>`, `findings.py stats`).
2. Глубокий ресёрч — отчёт в `docs/research/` (структура — README там);
   findings ссылается на отчёт (`--source`).
3. Ресёрч менял код/доки — обновить базу проекта: `build.py` / `--refresh`.
4. Метрики поисков — `search.py --stats`.
