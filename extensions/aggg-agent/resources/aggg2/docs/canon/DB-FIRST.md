# Поиск через базу данных

Перед ответом на вопрос о содержимом воркспейса/проекта — **сначала искать
в базе**, потом отвечать. Не по памяти.

## Базы

| База | Что в ней |
|---|---|
| `aggg2.db` | все файлы папки AGGG2.0 (скиллы, доки, AGENTS.md) |
| `sherpa-voice.db` | исходники sherpa-voice + история транскриптов (`--extra-files ~/.cache/sherpa-voice/history.md`) |
| `research.db` | находки и выводы ресёрча + журнал задач (таблицы `findings`, `tasks`) |

## Новая база для проекта — две команды, без правки кода

Любая папка собирается в свою базу (одна команда); MCP-тулы (`list_dbs`,
`search`, `symbol`, граф) подхватывают её автоматически — каталог `db/`
сканируется, не зашит списком:

```bash
python3 db-tools/build.py -r projects/<проект> -o db/<проект>.db
```

**Индексация — обязательный первый шаг работы над ЛЮБЫМ проектом:** нет
базы → `build.py` (п.6). Код не пишется и не правится, пока проект не
проиндексирован и не разобран через базу. **Сторонние проекты — та же
схема, своя база** (`build.py -r /путь -o db/<имя>.db` / MCP
`index_project`; lazy-индексация по требованию, таймаут 180с). Свежесть —
автоматическая (meta.root в базе; сторож `fresh.py [db|--check]` зовут
MCP search/search.py/repomap/search_all) → инкрементальная пересборка.
Перед работой: `search.py --refresh -r <корень>` (mtime→sha256, секунды).
Устаревшая база = ложный ответ.

Выбирать базу по теме: скиллы/паттерны → `aggg2.db`; код/история ассистента
→ `sherpa-voice.db`; «мы это уже смотрели» → `research.db`.

**Живая спека проекта** (living spec, Vercel Labs/Augment): перед работой
над проектом с живым доком (PRODUCT.md/STATE.md/spec в `docs/` проекта)
ПЕРВЫМ читать его: решения, ограничения, «не трогать», открытое; после
правок — обновлять. CHANGELOG = история, живой док = текущее состояние;
расхождение спеки с кодом = ложный источник. Указатели живут в файлах
проекта, не в каноне.

## Правило

1. Получил запрос — определи, относится ли он к файлам одной из баз.
2. Если да — поиск по базе ДО формулирования ответа.
3. Найденное — факты. Остальное — предположения, требующие проверки.
3б. **Пусто — лестница, не тупик:** (1) короче, 2-3 слова, без склонений
    и AND-цепочек (морфология-фолбэк сработает сам); (2) `--substring`;
    (3) другая база / `search_all.py`; (4) `findings.py search`;
    (5) свежесть: `--refresh` / `build.py`. **Wiki/ агент НЕ грепает** —
    только база (`db: wiki`), grep — человеку (WIKI.md). Всё пусто —
    честно «не нашёл в базе».
4. После ресёрча/эксперимента/разбора — выводы в `research.db`
   (`findings.py add`), иначе знание теряется.
5. **База — и перед внедрением.** Новый механизм/инструмент/решение —
   сначала `findings.py search` по теме + осмотр существующего (scripts/,
   db-tools/, файлы проекта): возможно, уже делалось или уже есть
   (урок: поставили chezmoi, не посмотрев на готовые `scripts/install_*.py`).
6. **Проект пишется через базу (DB-FIRST), не с головы:**
   (1) нет базы — `build.py -r projects/<проект> -o db/<проект>.db`;
   (2) свежесть перед работой — `search.py --refresh -r <корень>`;
   (3) поиск/понимание кода — ВСЕГДА через базу (`--symbol/--calls`,
   FTS, `findings.py search`), не чтение файлов «с головы»; глубина —
   agent-lsp (типы/ссылки); (4) код пишется поверх этого разбора;
   (5) после — находки в research.db. Код «из головы» без сверки с базой =
   нарушение.
7. **Журнал задач — в базе.** «Что мы делали когда-то» → `tasks.py`
   (таблица `tasks`; `add/list/close/block/search`). Находки = «что знаем»,
   журнал = «что делали и чем кончилось». Нетривиальная задача — завести
   и закрыть (CYCLE.md фазы 0 и 8).
8. **История файлов — из git в базу.** «Кто менял файл, когда, как часто»
   → `githist.py` (таблицы `commits`, `file_history`, `commit_files`;
   `refresh/file/hotspots`; свежесть ловит doctor.py). History-aware поиск
   из индекса, не из памяти (паттерн Sourcegraph/zoekt; замер: 0.00с,
   7.6 МБ на всё AGGG2.0).

## Находки и выводы (research.db)

База для того, что НЕ лежит в файлах проекта: результаты ресёрча,
сравнения инструментов, решения с причинами, грабли. Как вести ресёрч —
CAMOUFOX.md.

```bash
python3 db-tools/findings.py add "Тема" --text "вывод/факт..." --tags "mcp lsp"
python3 db-tools/findings.py search mcp
python3 db-tools/findings.py search "вывод AND LSP"
python3 db-tools/findings.py list [--tags lsp]
python3 db-tools/findings.py supersede 12 --note "опровергнуто 17.08"  # ретракшн, не удалять
python3 db-tools/findings.py consolidate --days 30 [--apply]           # архив кандидатов
python3 db-tools/findings.py search mcp --status superseded|all        # live = только active
```

Правило записи: тема короткая и конкретная; `--text` — вывод, который
пригодится через месяц (что выбрали, почему, что отвергли, ссылки);
`--tags` — 2-4 слова. Перед «мы это уже разбирали» — сначала search.

**Связи находок:** `link add <id> <id> --kind related|extends|contradicts
--note "..."`, `related <id> [--depth 2]` (цепочки знаний, KG-паттерн),
`link list <id>`, `show <id>`, `stats`. Откуда взято — `--source <путь/URL>`.

**Отчёты глубокого ресёрча** — `docs/research/<дата>-<тема>.md` (шаблон —
`docs/research/README.md`): сырьё в отчёте, вывод в research.db с `--source`.

**Авто-кандидаты из истории сессий:** `python3 db-tools/extract_findings.py`
(показ) → `--add 1,3,7` (добавка) — знания из транскриптов не умирают.

## Как искать

```bash
python3 db-tools/search.py "<запрос>"                          # база AGGG2.0
python3 db-tools/search.py -b db/sherpa-voice.db "<запрос>"   # своя база
python3 db-tools/search.py "паттерн AND агент"   # составной запрос
python3 db-tools/search.py --limit 5 "<запрос>"
python3 db-tools/search.py --refresh "<запрос>"  # свежесть ДО поиска;
# запрос пишем ДО --extra-files, иначе nargs='*' съест его как файл
```

Или sqlite3 напрямую:
```bash
sqlite3 db/aggg2.db "SELECT rel_path FROM files_fts WHERE files_fts MATCH 'запрос';"
```

**По ВСЕМ базам сразу** («где это лежит»): `search_all.py "запрос"
[--substring]` / MCP `search_all` (srclight-паттерн).

**Подстрока/склонения** — триграм: при пустом FTS search.py сам делает
авто-фолбэк в триграм-индекс (`--substring` — явно). «переосмыслени»
найдёт «переосмысление».

## Карта вместо чтения файлов (repo-map)

Ориентация в коде — **СНАЧАЛА КАРТА, потом файлы** (паттерн repo-map,
Agent Patterns Catalog; слепой греп/чтение = нарушение):

```bash
python3 db-tools/repomap.py project --db db/<имя>.db --tokens 1500
python3 db-tools/repomap.py file <rel_path> --db db/<имя>.db
# MCP: repo_map(db, path, tokens)
```

Карта = PageRank по импорт-графу из базы + символы с сигнатурами в
токен-бюджете. Файл читается ПОСЛЕ карты, и только если карта показала
(40-60% токенов агента — ориентация; карта режет их, ContextSniper
ICML2026: −51% без потери качества).

## Что делать с результатами

- Найден файл → открыть и читать, не пересказывать по памяти.
- Несколько кандидатов → посмотреть все, выбрать релевантное.
- Файл по теме — **ссылаться на него в ответе** (`skills/.../SKILL.md`).
- Совпадение в сниппете (`[…]`) — открыть и процитировать.

## Когда поиск не нужен

- Вопрос не про содержимое папки (общий вопрос, код вне проекта).
- Уже искали по этому запросу в этой сессии и знаем ответ.
- Вопрос про сам поиск: как устроена база, что в ней.

## Если ничего не нашлось

- Переформулировать: короче (2-3 слова, без AND-цепочек — каждая связка
  режет результат до нуля), без склонений. Язык: содержимое файлов — на
  РУССКОМ, имена файлов/символов — латиницей («windows»). Смешанные
  запросы («delete file») дают 0 — мисматч языка (замер 14.08: 32% пустых).
- Свежесть: `search.py --refresh` (инкрементально; полная — `build.py --full`).
- Файл в папке, но не в базе — база устарела, пересобрать и искать снова.
- «Мы это уже разбирали» — `findings.py search <тема>`.
- После всего пусто — честно «не нашёл в базе», не выдумывать.

## Почему так

В базе лежит то, что уже написано и проверено в этой папке. Искать по
ней — дешевле, чем угадывать, и точнее, чем по памяти: это единственный
источник фактов о содержимом проекта.
