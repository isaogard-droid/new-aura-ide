# fable-loop — оркестрация по методу

Как исполнять fable-method, когда работы много: что в главном потоке, что раздаётся субагентам, что атакуется перед сдачей. Полный текст: `skills/fable-loop/SKILL.md` (метод — `skills/fable-method/SKILL.md`).

## Зачем нужен (какую боль закрывает)
Метод говорит ЧТО проверять; loop — КТО делает работу. Без него главный агент тащит всё сам: контекст забивается, параллельные задачи идут последовательно, проверка — «сам себя проверил». Роли loop: сборщики доказательств — субагенты, решения и правки — главный поток, атака на результат — отдельные судьи.

## Четыре стадии
**Stage 1 — PLAN.** Классификация + done с названной проверкой. **Фан-аут доказательств**: субагенты-сборщики ПАРАЛЛЕЛЬНО, одним сообщением: код — explore-агент по каждой области, факты — ресёрч-агент. Бюджет: батч + follow-up; третий — с причиной. Артефакт-план: классификация, done+проверка, доказательства, ОДИН рекомендованный подход (альтернативы — по строке), скоуп, риски, чеклист. **Decision gate**: задача-форма и обратимая — идти без спроса; план-форма (неясный скоуп, необратимое, наружу) — показать план и СТОП.
**Stage 2 — EXECUTE.** Чеклист в главном потоке (решения и правки — только там; наружу — только поиск и проверки). Правила метода: intent gate до правки поведения, recall gate до первого использования неоткрытого, минимальная правка, ничего не разрушать не посмотрев. Механические повторения — субагентам, с изоляцией копий. Сюрприз — вернуться в PLAN.
**Stage 3 — VERIFY (adversarially).** Названную проверку прогнать самому: критерий done наблюдается + окружение здорово (build/тесты/линт). Для важных изменений — **атакующие** субагенты (1-3, параллельно), каждый с РАЗНЫМ углом: «докажи, что правка неверна», «найди вход, который ломает», «сверь со спекой», «докажи, что вышел за скоуп». Находка, пережившая твою проверку — новая работа в Stage 2. Предел: 3 цикла фикс-проверка — стоп и отчёт.
**Stage 4 — AUDIT + REPORT.** Самопроверка (followed/skipped/faked), починка одного прохода. Отчёт: исход первым, доказательства проверки, честные оговорки, follow-up только из работы. Номеров стадий в отчёте нет.

## Когда использовать
- нетривиальное многошаговое (оркестрация нужна); «/fable-loop», «сделай как Fable»; параллельные независимые направления (3+ областей).
НЕ для: тривиального (гейт), чистых вопросов (хватит fable-method), внутри уже оркестрируемой GSD-фазы.

## Модельная экономика
Loop не зависит от модели: сборщики и атакующие — на дешёвых моделях; главный поток (решения, правки) — на самой сильной; атакующим — выше effort, чем сборщикам.
