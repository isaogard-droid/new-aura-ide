# A. ИСТИНА И ДЕНЬГИ (данные, биллинг, side-effects)

---

## 1. MONEY PATH IS SACRED
**Принцип:** Любой путь, где списывают/начисляют/оплачивают — особый класс кода.
**Правило:** Lock/транзакция, идемпотентность, лог на каждое событие, тест на double-submit.
**Антипаттерн:** «Потом добавим защиту»; except: pass вокруг charge.
**Проверка:** Дважды нажал «оплатить/проверить» → баланс +X, не +2X.

---

## 2. IDEMPOTENCY BY DEFAULT FOR CREDITS
**Принцип:** Повтор доставки события не должен менять итог.
**Правило:** Ключ операции (invoice_id, event_id) + флаг credited + early return.
**Антипаттерн:** add() без проверки «уже сделано».
**Проверка:** Прогнать handler 2 раза подряд — второй no-op.

---

## 3. SEPARATE BUCKETS FOR DIFFERENT MONEY SEMANTICS
**Принцип:** Trial, promo, purchase, subscription — разные сущности, не одно поле.
**Правило:** Отдельные балансы/флаги + явный порядок списания.
**Антипаттерн:** Всё в `balance` → промо прячет покупку, renew затирает paid.
**Проверка:** Можно ли описать продукт одной формулой списания без «но если»?

---

## 4. HARD GATE BEFORE EXPENSIVE WORK
**Принцип:** Сначала проверка права/лимита/денег, потом CPU/API/LLM.
**Правило:** can_afford / quota check до внешнего вызова.
**Антипаттерн:** Сделали работу → «ой, лимит» → деньги сожжены.
**Проверка:** При нулевом балансе внешний API не вызывается (mock/spy).

---

## 5. CHARGE AFTER SUCCESS, NEVER ON FAILURE (default)
**Принцип:** Юзер платит за результат, не за попытку (если иное не в договоре).
**Правило:** success path → debit; error path → no debit (+ log).
**Антипаттерн:** Списали, потом упали — support тикеты.
**Проверка:** Инъекция ошибки провайдера → баланс не меняется.

---

## 6. LOG EVERY MUTATION OF VALUE
**Принцип:** «Кто/кому/сколько/когда» должно быть в логе без раскопок.
**Правило:** Одна строка на credit/debit/grant/refund с id субъекта и amount.
**Антипаттерн:** Только «ok» в UI, в логе тишина.
**Проверка:** grep по user_id восстанавливает историю списаний.

---

## 7. PLATFORM METADATA > LOCAL GUESS
**Принцип:** Источник правды платформы (duration, size, user id) над своим парсером.
**Правило:** Primary = platform field; fallback = local probe; floor = sane minimum.
**Антипаттерн:** Парсить ogg через wave «потому что так привычнее».
**Проверка:** Основной формат продукта проходит без fallback.

---

## 8. NO SILENT EXCEPT ON SIDE EFFECTS
**Принцип:** except: pass допустим на cleanup, недопустим на money/auth/data-loss.
**Правило:** Money path: log + fallback or fail loud. Cleanup: pass ok.
**Антипаттерн:** except Exception: pass вокруг charge/save/notify-critical.
**Проверка:** Code review: каждый bare except помечен зачем.

---

## 9. READ-MODIFY-WRITE UNDER LOCK
**Принцип:** «Прочитал → посчитал → записал» без блокировки = lost update.
**Правило:** Mutex/transaction на весь RMW; не на один UPDATE вслепую.
**Антипаттерн:** if balance > x: balance -= x без атомарности.
**Проверка:** Два параллельных charge не уводят в минус сверх правил.

---

## 10. ONE SOURCE OF TRUTH FOR BALANCE/STATE
**Принцип:** UI, кэш, лог — производные. Истина — хранилище.
**Правило:** Не чинить «отображение», пока SELECT не совпадает с ожиданием.
**Антипаттерн:** «В интерфейсе 30, в БД 12 — наверное кэш фронта» без проверки БД.
**Проверка:** Инцидент начинается с read storage, не с теории.
