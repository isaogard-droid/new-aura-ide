# N. УНИВЕРСАЛЬНЫЕ ПРИНЦИПЫ UX-НАВИГАЦИИ (часть 2: N24–N43)

Вынесено из `n-ux-navigation.md` (механическая резка god-файла, docs/canon/FILE-SIZE.md).

---

## N24. EMPTY CONTENT HIDES SECTION
**Принцип:** Если секция контента пуста — не показывать её заголовок и пустое место в UI.
**Правило:** `if content:` перед добавлением блока в результат.
**Антипаттерн:** Показать заголовок секции с пустым телом — путает пользователя.
**Признак:** Проверка `if content:` перед форматированием каждой секции.

---

## N25. CONSISTENT NAMING ACROSS ALL SURFACES
**Принцип:** Один и тот же режим/функция называется одинаково во всех частях UI: в настройках, в результатах, в истории, в кнопках.
**Правило:** Единый глоссарий терминов, используемых во всём UI.
**Антипаттерн:** В настройках «Авто-краткое», в результатах «Краткое содержание», в кнопке «Кратко» — пользователь путается.
**Признак:** Термин для режима един во всём UI.

---

## N26. CACHE HIT METADATA
**Принцип:** При кэшированном результате логировать/показывать метку «из кэша», чтобы отличать от реальных вызовов.
**Правило:** `cost = 0; isCached = true` в метаданных результата.
**Антипаттерн:** Логировать cost/time без различия cached/real — метрики врут.
**Признак:** В метаданных результата есть признак cached и флаг стоимости.

---

## N27. TEMPORARY STATUS LIFECYCLE
**Принцип:** Временные статусные сообщения («загружаю…», «обрабатываю…») удаляются перед показом финального результата.
**Правило:** Создать статус → удалить перед финалом → показать результат.
**Антипаттерн:** Статус остаётся под результатом — замусоривает интерфейс.
**Признак:** Перед каждым показом результата есть удаление статусного сообщения.

---

## N28. UI CLEANUP EXCEPTION IS SAFE
**Принцип:** `catch {}` (bare except) допустим только для UI-cleanup (удаление статуса, закрытие диалога), не для бизнес-логики.
**Правило:** `try: deleteStatus(); catch {}` — статус мог быть уже удалён. Безопасно игнорировать.
**Антипаттерн:** `catch {}` вокруг списания денег, сохранения данных, вызова API.
**Признак:** Каждый bare except имеет комментарий или очевидно относится к UI-cleanup.

---

## N29. ROUTE PATTERN CO-EVOLUTION
**Принцип:** При добавлении нового контекста в маршруты (fresh/stale, preview/export) — обновить regex/pattern роутера, чтобы он принимал новые значения.
**Правило:** `pattern = r"^action:\w+:\d+:(?:\d+|fresh)$"` — разрешает и старый и новый форматы.
**Антипаттерн:** Оставить старый pattern — новые маршруты не матчатся.
**Признак:** Regex содержит альтернативу для нового контекста, если он был добавлен.

---

## N30. COMPLETE HANDLER REGISTRATION
**Принцип:** Новый handler должен быть зарегистрирован во всех точках входа, где это требуется (роутер, карта функций, DI-контейнер).
**Правило:** Чеклист: 1) файл handler'а, 2) роутер, 3) карта/словарь handler'ов, 4) экспорт.
**Антипаттерн:** Handler есть в файле, но отсутствует в роутере — не вызывается.
**Признак:** Grep имени handler'а находит все 3-4 точки регистрации.

---

## N31. TYPE WIDENING WITH BACKWARD COMPATIBILITY
**Принцип:** Когда тип параметра расширяется (int → int | string), старые значения продолжают работать.
**Правило:** `page: int | string` — старые вызовы с int не ломаются, новые со string работают.
**Антипаттерн:** Оставить int и передавать string — тайпчекер/компилятор ругается.
**Признак:** Тип параметра объединённый (union) с сохранением старого типа.

---

## N32. FULL CONTEXT CHAIN THROUGH ALL ACTIONS
**Принцип:** Все кнопки действий (экспорт, генерация, шаринг) несут полный контекст возврата, а не только идентификатор объекта.
**Правило:** `context = isFresh ? "fresh" : pageNumber` — передаётся в каждое действие.
**Антипаттерн:** Экспорт всегда возвращает на page=0 — после экспорта пользователь теряет позицию.
**Признак:** Контекст возврата вычисляется из флага fresh и передаётся во все дочерние действия.

---

## N33. BACKWARD-COMPATIBLE SIGNATURE EVOLUTION
**Принцип:** При добавлении нового параметра в публичную функцию — новый параметр имеет значение по умолчанию, равное старому поведению.
**Правило:** `def func(..., newParam: Type = oldValue)` — существующие вызовы не меняются.
**Антипаттерн:** Новый обязательный параметр — все старые вызовы падают.
**Признак:** Новый параметр имеет default-значение, сохраняющее обратную совместимость.

---

## N34. PAGINATION CONTEXT IN CHUNKS
**Принцип:** При разбивке результата на части каждая часть имеет ссылку возврата с контекстом.
**Правило:** `backTarget` в каждом фрагменте; последний фрагмент тоже с backTarget.
**Антипаттерн:** Только первый или только последний фрагмент с кнопкой возврата.
**Признак:** В цикле по фрагментам у каждого вызова есть ссылка возврата с контекстом.

---

## N35. TAGS SIGNAL SOURCE, NOT JUST PRESENCE
**Принцип:** Тег/метка рядом с контентом должна показывать не только факт наличия, а источник: auto-generated, manually-requested, отсутствует.
**Правило:** Три состояния тега с разными иконками/цветами: auto, manual, none.
**Антипаттерн:** Бинарный тег «есть/нет» — не отличить автоматическое от ручного.
**Признак:** Иконка/цвет тега однозначно передаёт источник контента, а не только его наличие.

---

## N36. COMMAND CONSOLIDATION HUB
**Принцип:** Разрозненные команды/действия собираются в один хаб: кнопка → компактное inline-меню, а не раскиданы по клавиатуре или спрятаны в /help.
**Правило:** Одна primary-кнопка открывает inline-меню со всеми связанными действиями. Действия делегируют существующим handler'ам.
**Антипаттерн:** 15 отдельных кнопок или /commands, которые надо запоминать.
**Признак:** Все связанные действия доступны в 2 тапа от главного экрана.

---

## N37. TWO-TIER NAVIGATION: SECTIONS → ACTIONS
**Принцип:** Основная клавиатура — для разделов верхнего уровня (Баланс, История, Управление); inline-меню — для под-действий внутри раздела (Авто-краткое, Контекст, Купить). Никогда не смешивать уровни.
**Правило:** Keyboard = точки входа в разделы (3-5 кнопок). Inline = действия внутри раздела (2-6 кнопок).
**Антипаттерн:** Inline-меню на основной клавиатуре; или действия разных уровней вперемешку.
**Признак:** Клавиатура содержит только названия разделов; заход в раздел показывает список действий.

---

## N38. BUTTON STYLE BY SEMANTICS
**Принцип:** Цвет/стиль кнопки передаёт смысл: primary (синий) = навигация, success (зелёный) = покупка/позитив, danger (красный) = разрушительное. Не произвольное украшение.
**Правило:** Назначать style по категории действия, не по эстетике. Primary для переходов, success для монетизации.
**Антипаттерн:** Случайные цвета «потому что зелёный красивый».
**Признак:** Пользователь угадывает поведение кнопки по одному цвету.

---

## N39. EMOJI DISCIPLINE: CLEAN BUTTONS, RICH MESSAGES
**Принцип:** Интерактивные элементы (кнопки) содержат только текст, без эмодзи. Эмодзи — в read-only контенте: статусах, заголовках, информационных сообщениях.
**Правило:** Button labels = plain text. Message bodies = эмодзи разрешены. Callback data никогда не содержит эмодзи.
**Антипаттерн:** «📊 Баланс» как кнопка — эмодзи занимает место, снижает читаемость, по-разному рендерится на платформах.
**Признак:** Grep по кнопочным label'ам на эмодзи → ноль результатов.

---

## N40. CALLBACK DELEGATION, NOT DUPLICATION
**Принцип:** Новые точки входа (inline-меню, альтернативные кнопки) делегируют существующим handler'ам через adapter, никогда не дублируют логику.
**Правило:** Adapter (SimpleNamespace/passthrough) из полей callback → вызов существующего handler'а. Один источник истины для каждого действия.
**Антипаттерн:** Скопировать логику cmd_summary в on_manage callback — два места для багов.
**Признак:** Каждый callback-handler это <5 строк routing + adapter; бизнес-логики ноль.

---

## N41. UI ENTRY POINT TESTS: PRESENCE + ROUTING
**Принцип:** Для каждого нового UI-элемента два теста: 1) элемент существует (кнопка в клавиатуре), 2) элемент работает (callback направляет в правильный handler).
**Правило:** test_X_exists + test_X_routes_to_Y — минимум два теста на каждое UI-добавление.
**Антипаттерн:** Только ручное тестирование новых кнопок.
**Признак:** Grep по label кнопки находит минимум одну test_-функцию с assert на присутствие.

---

## N42. NAME FOR FUNCTION, NOT NOVELTY
**Принцип:** UI-лейблы описывают что пользователь найдёт/сделает, а не креативные названия, требующие объяснения. «Управление» > «Старта» когда /start уже занят другой семантикой.
**Правило:** Лейбл отвечает на вопрос «что внутри?» или «что произойдёт?». Избегать переиспользования зарезервированных платформой терминов.
**Антипаттерн:** «Логово», «Пульт» — креативно но непонятно.
**Признак:** Новый пользователь угадывает содержимое по лейблу за <3 секунды.

---

## N43. POST-REFINEMENT LABEL AUDIT
**Принцип:** После реализации — пройтись по всем новым лейблам и убрать декоративные элементы (эмодзи, лишние знаки), которые попали в кнопки на этапе прототипирования.
**Правило:** Перед финальным деплоем: grep по label'ам кнопок → удалить эмодзи → обновить тесты → перезапустить.
**Антипаттерн:** Оставить декоративные эмодзи в кнопках потому что «уже работает».
**Признак:** Финальный diff содержит удаление эмодзи из button-лейблов и обновление assert в тестах.
