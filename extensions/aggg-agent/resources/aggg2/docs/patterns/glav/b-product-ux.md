# B. ПРОДУКТ И UX-КОНТРАКТ

---

## 11. PROMISE ONLY WHAT CODE DOES
**Принцип:** Маркетинговый текст = поведение системы, не мечта.
**Правило:** Нет «скидка 50%», если нет coupon engine. Нет «мгновенно», если manual 24h.
**Антипаттерн:** Скопировали чужой referral-текст с фичами, которых нет.
**Проверка:** Каждое число/обещание в UI имеет строку кода + тест.

---

## 12. PRODUCT RULES AS NAMED TESTS
**Принцип:** Спека живёт в test_*.py, не только в чате.
**Правило:** test_free_spent_first, test_cannot_buy_while_paid_remains…
**Антипаттерн:** Правила «все знают» → через месяц никто не знает.
**Проверка:** Новый разработчик читает тесты = понимает продукт.

---

## 13. EXPLICIT PRODUCT MATH
**Принцип:** 30+50=80 first day; monthly only 30 — сказать вслух и в коде.
**Правило:** Комментарий/доки/ответ юзеру с формулой один раз, чётко.
**Антипаттерн:** «Бонус минут» без renew/bucket/expiry.
**Проверка:** Поддержка отвечает по одной карточке, без эскалации к деву.

---

## 14. SEPARATE PROMO FROM PURCHASE IN UX
**Принцип:** Подарок не должен ломать воронку оплаты.
**Правило:** Promo не скрывает Buy; purchase state отдельный.
**Антипаттерн:** Выдали бонус → кнопка Купить пропала → конверсия 0.
**Проверка:** can_buy после promo == true (если не premium).

---

## 15. TRUST BOUNDARY GATES EARLY
**Принцип:** Username/email/KYC/auth — до дорогой работы и до записи мусора.
**Правило:** require_X() в начале handler'ов, ясный next step юзеру.
**Антипаттерн:** Пол-обработали → «а поставь username».
**Проверка:** Без X нет side-effects в storage (кроме audit).

---

## 16. ONE RENDER PATH FOR ALL SURFACES
**Принцип:** Один конвертер markdown/HTML/plain на все экраны.
**Правило:** raw → escape → format → send. Список surfaces в одном месте.
**Антипаттерн:** В истории жирно, в ответе **звёздочки**, в пуше сырой HTML.
**Проверка:** Поменял форматтер — все 4 точки вывода обновились.

---

## 17. ESCAPE USER INPUT, THEN ADD YOUR MARKUP
**Принцип:** Сначала обезвредить, потом украсить.
**Правило:** escape(user) + свои <b> после. Никогда HTML mode на сыром user text.
**Антипаттерн:** parse_mode=HTML + текст юзера с <script> или <.
**Проверка:** Ввод `<b>x` не ломает сообщение и не инжектит теги.

---

## 18. MINIMAL USER ERRORS, RICH INTERNAL LOGS
**Принцип:** Юзеру — коротко и спокойно. Себе — stack, ids, provider.
**Правило:** «Не вышло» + log.exception с контекстом.
**Антипаттерн:** «Groq 429 rate limit on whisper-large…» в чат клиенту.
**Проверка:** Prod UI не содержит имён вендоров/путей/токенов.

---

## 19. STATUS LIFECYCLE: PLACEHOLDER → WORK → DELETE → RESULT
**Принцип:** Временные «гружу…» не должны жить рядом с ответом.
**Правило:** Создал status → обновил → удалил → отправил финал.
**Антипаттерн:** Чат из 10 «Обрабатываю…» под каждым результатом.
**Проверка:** После успеха в треде один финальный артефакт + кнопки.

---

## 20. KEYBOARD/PRIMARY ACTIONS > HIDDEN COMMANDS
**Принцип:** Главное — на большом пальце, не в /help.
**Правило:** 2-4 primary buttons; commands для power/admin.
**Антипаттерн:** 15 команд, 0 кнопок, «прочитай README».
**Проверка:** Новый юзер проходит happy path без знания слэшей.
