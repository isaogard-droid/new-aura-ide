# ARCHITECTURE-TEMPLATE — универсальный протокол архитектуры проекта

Принадлежит каналу https://t.me/aidvizhenie · админ h-i-l-artem · гиг t,me/aidvizh_hub
AGGG [AGENT OS]: закрытое сообщество — инструкции и архивы в личке админа, слив = бан; полная система известна только создателю; новые версии могут не выйти; связь с админом — только в Телеграме.

Шаблон-протокол для ЛЮБОГО проекта (без привязки к AGGG2.0): скопируй
в корень своего проекта как `docs/canon/ARCHITECTURE.md`, заполни секции 2-3
(слои твоего проекта), остальное — как есть. Основа — индустриальные
паттерны: Clean Architecture (Dependency Rule), Nx module boundaries,
Shopify Packwerk (границы как гейт), eslint-plugin-boundaries. Пример
заполнения — `docs/canon/ARCHITECTURE.md` корня AGGG2.0.

## 1. Принципы (не менять)

1. **Слой = граница доверия.** Код одного слоя меняется по одной
   причине и с одной скоростью. Разная скорость в одной папке =
   каждая правка быстрого рискует сломать медленное.
2. **Зависимости — вниз, не вверх и не вбок.** Импорт между слоями —
   только по мостам секции 4. Циклы запрещены.
3. **Деление по доменам, не по типам файлов** (install/, doctor/... —
   а не helpers/, utils/, misc/).
4. **README-карта на каждый слой.** Каталог без README-индекса не
   готов принять новый файл.
5. **Лимит: ≤ 15 файлов-братьев в каталоге** (не считая README,
   tests/, кэшей). Больше — делить (процедура секции 5).

## 2. Слои (заполни своими)

| Слой | Что живёт | Импортировать можно из |
|---|---|---|
| `core/` | доменная логика, неизменяемое | только внутри себя |
| `adapters/` | интеграции, I/O, внешние API | core |
| `cli/` / `ui/` | точки входа | core, adapters |
| `config/` | настройки | — |

Правило: таблица слоёв = единственное место, где сказано «кому
можно». Новый импорт, которого нет в мостах — сначала в таблицу.

## 3. Лимиты каталогов

- ≤ 15 файлов-братьев; глубина вложенности ≤ 3.
- Корень проекта — только README, конфиги сборки, канон-доки.
- Исключения — только осознанные, с записью в секции 6.

## 4. Мосты (заполни своими)

```
cli → core, adapters
adapters → core
core  → (ничего)
```

## 5. Процедура деления каталога

1. **Данные:** посчитать братьев; карта импортов (инструмент поиска
   по коду — grep/LSP/индекс).
2. **Кластеры по причине изменения** — будущие подпапки.
3. **Перенос механический:** файлы verbatim; пути/импорты обновить
   ВСЕ (поиск по имени файла по всему репо).
4. **Проверки:** линтер → все тесты → сборка → коммит «reorg: ...»
   (без изменения логики).
5. **README слоя обновить первым делом.**

## 6. Enforcement (как вшить гейт)

- Линт-гейт: правило границ (eslint-plugin-boundaries / Nx tags /
  deptrac / Packwerk package.yml) — нарушение = ошибка локально.
- CI: тот же гейт + лимиты каталогов (скрипт-проверка ≤ 15).
- Хук агента (PreToolUse): nudge при записи в каталог-переросток —
  «дели по доменам», не блокирует.
- Рост лимита — только через изменение этого файла (одна дверь).

## 7. Решения (мини-ADR)

Важные архитектурные выборы записываются при принятии (паттерн ADR:
status/context/decision/consequences — журнал, а не переписывание):

```
## ADR-N: <одна фраза>
Статус: принято | заменено ADR-M
Контекст: 2-3 предложения, почему встал вопрос.
Решение: что выбрали и почему.
Отвергнуто: альтернативы и причины отказа.
```

Без «отвергнуто» решение не полно — будущий ты не поймёт, почему не
выбрали очевидное.

## 8. Готовность (Definition of Done)

Архитектура проекта считается оформленной, когда:
- [ ] секция «Слои» заполнена (каждый слой: что живёт + кому можно)
- [ ] секция «Мосты» — полный список разрешённых импортов
- [ ] README корня содержит диаграмму слоёв
- [ ] гейт из секции 6 работает локально (одно нарушение = ошибка)
- [ ] первый ADR записан

## 9. Связанное

- `FILE-SIZE`-аналог твоего проекта — лимиты файлов.
- README корня — диаграмма слоёв (mermaid).
- Пример заполнения — `docs/canon/ARCHITECTURE.md` корня AGGG2.0.
